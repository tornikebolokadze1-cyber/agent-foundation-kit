# critic-ების დრილი (D-070)

**რისთვის.** სამი კრიტიკოსი (`.claude/agents/critic-correctness.md`, `critic-security.md`, `critic-quality.md`) კოდს
ამოწმებს, მაგრამ აქამდე არავის უჩვენებია, რომ რომელიმე მათგანს **შეუძლია** შეცდომის დაჭერა. კრიტიკოსი, რომელიც
ყოველთვის „დეფექტი არ არის"-ს ამბობს, და კარგი კრიტიკოსი სუფთა კოდზე ერთსა და იმავე ხაზს ბეჭდავს ([[ADR-0006-deterministic-gates-and-evals]]). ეს დრილი
თითოეულს აძლევს სუფთა საკონტროლო კოდს და კოდს, რომელშიც მისივე ლინზის ერთი შეცდომა განზრახ ჩადეს, და ამოწმებს
პასუხს — მოდელი მოდელს არ აფასებს.

**როგორ.** თითო შემთხვევა ცალკე `claude -p` სესიაა დროებით საქაღალდეში, სადაც მხოლოდ ამ შემთხვევის ფაილებია
(`--restricted`, მხოლოდ Read/Grep/Glob, ის მოდელი, რომელსაც კრიტიკოსის frontmatter ასახელებს). ვერდიქტი მისი ბოლო
ხაზიდან იკითხება. მერე მთელი პასუხი `tools/check_findings.py`-ში გადის, იმავე საქაღალდით: მიგნება, რომლის ფაილი, ხაზი
ან ციტატა არ დასტურდება, არ ითვლება ([[REVIEW]]). ამიტომ ARMED მხოლოდ ისაა, ვინც **სწორ ადგილას** იპოვა შეცდომა;
საკონტროლო კი სუფთა მხოლოდ მაშინაა, როცა `VERDICT OK`-თან ერთად ნული სტრიქონია — ასე ითხოვს თავად კრიტიკოსის
კონტრაქტი. უსაფრთხოების კრიტიკოსს მესამე შემთხვევაც აქვს: ფაილი იკითხება helper-ით, რომელიც საქაღალდეში არ არის, ანუ
გადამწყვეტი ფაქტი არ ჩანს. სწორი პასუხი აქ UNRESOLVED ხაზი და `VERDICT INCONCLUSIVE`-ია: FAIL ვარაუდს გაბერავდა,
OK კი წაუკითხავ helper-ს ენდობოდა.

```bash
bash .claude/hooks/py.sh evals/critics/run.py                          # სამივე კრიტიკოსი, საკონტროლოთი
bash .claude/hooks/py.sh evals/critics/run.py --critic critic-security # მხოლოდ ერთი
```

ფასიანია (თითო შემთხვევა ერთი მოდელის სესიაა) და ხელით ეშვება — commit-ის შემოწმება მას არ უშვებს. შედეგი
`results-<თარიღი-დრო>.json`-ში ინახება. გასვლის კოდი: 0 — ყველა ARMED; 1 — რომელიმე DEAD (ჩუმად დარჩა, სხვაგან
„იპოვა" ან მისი სტრიქონები არ დასტურდება); 2 — INCONCLUSIVE (საკონტროლო სუფთა არ დაბრუნდა, გამოძახება ჩავარდა ან
ბოლო ხაზი აკლია).

**პირველი გაშვება (2026-10-20, `results-2026-10-20-2017.json`, $0.26).** შვიდი შემთხვევიდან ექვსი ARMED იყო; მეშვიდე —
უსაფრთხოების კრიტიკოსის UNRESOLVED შემთხვევა — DEAD-ად ჩაითვალა, თუმცა კრიტიკოსმა ზუსტად სწორად უპასუხა
(INCONCLUSIVE, დაკარგული ფაქტი — `safe_join`-ის კოდი, და ვინ აჩვენებს — `storage` მოდული). შეცდომა შემმოწმებელში
იყო: `check_findings.py` UNRESOLVED ხაზის მეოთხე სვეტში (დაკარგული ფაქტის აღწერაში) ციტატას ეძებდა, ის კი არაფერს
ციტირებს. გასწორდა, დრილს თავისი შემთხვევა დაემატა, და იმავე შენახულ პასუხებზე ხელახალი შეფასება შვიდივეს ARMED-ს
აძლევს. ცოცხალმა გაშვებამ ის იპოვა, რაც დრილის ხელით დაწერილმა შემთხვევებმა ვერ იპოვა (L-010-ის მსგავსად).
