# კარიბჭეები (gates)

კარიბჭე (gate) არის მანქანური შემოწმება, რომლის შედეგზე კამათი შეუძლებელია: ან გავიდა, ან ჩავარდა, ან ვერ გაეშვა. ის არ ენდობა მოდელის სიტყვას „მუშაობს" — თავად ამოწმებს. გადაწყვეტილება: [[ADR-0006-deterministic-gates-and-evals]].

## გაშვება

```bash
bash .claude/hooks/py.sh tools/gates/gate.py                 # ყველა ჩართული gate, მთელი პროექტი
bash .claude/hooks/py.sh tools/gates/gate.py --list          # ყველა gate, გამორთულებიც, მიზეზით
bash .claude/hooks/py.sh tools/gates/gate.py --pre-commit    # რასაც .githooks/pre-commit უშვებს
bash .claude/hooks/py.sh tools/gates/gate.py --files a.md    # მხოლოდ ეს ფაილები (Stop hook ასე იყენებს)
bash .claude/hooks/py.sh tools/gates/gate.py --only graph,json  # მხოლოდ ეს gate-ები
bash .claude/hooks/py.sh tools/gates/drill.py                # ყოველი შემოწმება განზრახ ტყდება — უნდა დაიჭიროს
bash .claude/hooks/py.sh tools/gates/drill.py --only wiring  # დრილის მხოლოდ ეს ჯგუფები
bash .claude/hooks/py.sh tools/gates/drill.py --self-test    # დრილის შემოწმება: stub-ებით უნდა თქვას DEAD
```

`bash .claude/hooks/py.sh` ძრავის გამშვებია: Windows-ზე, macOS-სა და Linux-ზე Python 3.12-ს ან უფრო ახალს თავად პოულობს (Windows-ზე `py -3.12`-იც მუშაობს).

**შედეგი:** `0` — ყველა ჩართული gate გავიდა; `1` — რაღაც ჩავარდა; `2` — INCONCLUSIVE (ვერ გაეშვა, მაგ. `GITLEAKS_BIN` არარსებულ ფაილზე მიუთითებს, ან ნული ფაილი შეამოწმა). **SKIP** ნიშნავს „გამორთულია" — ეს არ არის „გავიდა", და ბოლო ხაზი ყოველთვის ამბობს, რამდენი gate-ი არ შემოწმებულა. `--only`-ში დაწერილი სახელი, რომელიც არცერთ gate-ს არ ჰქვია (მაგ. შეცდომით აკრეფილი), თავის ხაზს იღებს — `INCONCLUSIVE … ONLY-UNKNOWN` — და გაშვება `2`-ით მთავრდება: სახელი, რომლითაც არაფერი შემოწმდა, „გავიდა" არ არის (ნაცნობი gate-ები მაინც ეშვება). დრილშიც ასეა: `drill.py --only`-სა და `DRILL_GROUPS`-ში უცნობი ჯგუფი `DRILL-UNKNOWN-GROUP`-ია, exit `2`, და არაფერი ეშვება.

## სად ეშვება

- **ყოველ commit-ზე** — `.githooks/pre-commit` (`core.hooksPath = .githooks`, მხოლოდ ამ რეპოში — ამას პირველი სესიის დაწყებისას `.claude/hooks/firstrun.py` თავად რთავს). გვერდის ავლა (`--no-verify`) აკრძალულია.
- **ყოველი ტურის ბოლოს** — Stop hook ამოწმებს მხოლოდ იმ ფაილებს, რაც ამ სესიამ შეცვალა; ჩავარდნისას აგენტი აგრძელებს და ასწორებს.
- **ხელით** — ნებისმიერ დროს, ზემოთ მოცემული ბრძანებით.

დრილი commit-ზე მაშინ ეშვება, როცა commit-ში ძრავის ფაილია (`.claude/hooks/`, `.claude/settings*`, `.claude/skills/`, `.claude/agents/`, `.claude/rules/`, `.githooks/`, `tools/`, ორკესტრაციის კოდი); სხვა commit-ზე მისი ხაზი SKIP-ია და ამას პირდაპირ წერს. იგივე სია (`tools/engine_line.py`-ის `PREFIXES`) სესიის ბოლოს ხაზსაც კვებავს ([[ADR-0015-permission-windows-only-where-a-person-decides]]): რომელი ძრავის ფაილი შეიცვალა სესიის დაწყების შემდეგ და შეამოწმა თუ არა ის დრილმა — დრილი, რომელიც commit-ზე გავიდა, git-ის საქაღალდეში ქვითარს (receipt) ტოვებს; commit-ზე მთელი ძრავა მოწმდება, ამიტომ ქვითარი იმ ფაილსაც ფარავს, რომელიც უფრო ადრე შეიცვალა და მას შემდეგ უცვლელია. `--no-verify`-ით ან გამორთული შემოწმებით გაკეთებულ commit-ს ქვითარი არ აქვს, და მისი ფაილი ⚠-ით ჩანს, სანამ შემდეგი commit დრილს არ გაივლის; guard-სა და `.githooks/`-ს ⚠ ყოველთვის აქვს. ხაზს ეპიზოდი ინახავს (SessionEnd), `/session-close` მფლობელს სიტყვასიტყვით გადასცემს, შემდეგი სესიის დასაწყისი კი ადამიანს პირდაპირ აჩვენებს. მისი ჯგუფი `decision` მხოლოდ იქ მუშაობს, სადაც დისპეჩერის კოდია (`orchestration/decide.py`) — ამ შაბლონში ის არ არის, ამიტომ დრილი ამ ჯგუფს გამოტოვებს და ამას ბოლო ხაზშიც წერს (`LEFT OUT: decision …`).

`secrets` gate სრულ გაშვებაზე ოთხ რამეს ამოწმებს: staged ფაილებს, შეუნახავ ცვლილებებს, ისტორიას და git-ში ჯერ არდამატებულ ფაილებს (gitleaks-ის git-რეჟიმი ამ უკანასკნელს საერთოდ ვერ ხედავს, ამიტომ თითოეული ცალკე მოწმდება). commit-ის წინ მხოლოდ staged ფაილები მოწმდება. თუ gitleaks კომპიუტერზე არ არის, იმავე ფაილებს ძრავის საკუთარი სკანერი ამოწმებს (`tools/redact.py` — იგივე სია, რომლითაც sentinel მუშაობს), და შედეგის ხაზი ამას პირდაპირ წერს: მას entropy-ის ზღვარი არ აქვს და git-ის ისტორიას არ ამოწმებს (ADR-0011). ის იცნობს პროვაიდერების გასაღებების თავსართებს და, 2026-10-20-იდან, საიდუმლოს სახელით მინიჭებულ ბრჭყალებიან მნიშვნელობასაც (`named-secret`): სახელი საიდუმლოს სიტყვით მთავრდება (`DB_PASSWORD`, `api_key`, `client_secret`), მნიშვნელობა 8+ სიმბოლოა და ასოც აქვს და ციფრიც — ამიტომ `password = get_password()`, გარემოს ცვლადის სახელი და `${…}` შაბლონი გადის.

`budget` gate ზომავს, რამდენ ბაიტს ტვირთავს ყოველი სესია პირველ სიტყვამდე — CLAUDE.md და მისი იმპორტები, `paths:`-ის გარეშე წესები, skill-ებისა და agent-ების აღწერები — და ჩავარდება, თუ ჯამი `max_bytes`-ს აჭარბებს, ან თუ `max_bytes` მფლობელის ბოლო `/approve budget N`-ზე მაღალია. guard-ი (G7) იგივე ბიუჯეტს ყოველ ცვლილებაზე იცავს; სია: `bash .claude/hooks/py.sh tools/budget.py`.

`memory` gate ([[ADR-0017-memory-hierarchy-and-dreaming]]) ზედა ფენას ამოწმებს — იმას, რასაც ყოველი სესია სხვა რამის წაკითხვამდე ენდობა: გაკვეთილების ინდექსს (`memory/LESSONS.md`) და სამ auto-ბლოკს, რომელსაც დასაწყისის ბრიფი აჩვენებს (`progress.md`-ის „ახლა", `plan.md`-ის მიმდინარე ფაზა და `tasks/todo.md`-ის „ახლა / შემდეგი"). იქ ყოველი მტკიცება, რომლის შემოწმებაც მანქანას შეუძლია, მოწმდება. დასახელებული commit git-ში უნდა არსებობდეს; სხვა რეპოზიტორიის commit მისი სახელით იწერება (`kit:<sha>`), და მას gate აღარ ეძებს. კოდის ფორმატში დაწერილი ფაილის გზა ზუსტად იმავე ასოებით უნდა არსებობდეს. D-, P- და L-ნომერი თავის რეესტრში უნდა იყოს: დავალების ხაზად `tasks/*.md`-ში, წინადადებად `memory/PROPOSALS.md`-ში, გაკვეთილად ინდექსში. 14 დღეზე ძველი დასრულებული დავალება `tasks/todo.md`-იდან იშლება, ამიტომ მისი ნომერი ზედა ფენიდანაც უნდა წავიდეს. „drill (`ჯგუფი`)"-ში დასახელებული ჯგუფი დრილის `GROUPS`-ში უნდა იყოს. ბლოკი, რომელიც თავის ზღვარზე (`episodic.py`-ის `BLOCK_CAPS`) გრძელია ან 60 ხაზს აჭარბებს, ჩავარდება, რადგან ბრიფი მას გაჭრიდა. commit-ზე gate იმ ტექსტს კითხულობს, რომელსაც commit ჩაწერს; ფაილი, რომელსაც git არ ინახავს (`memory/graph/`, `.git/`), დისკზე მოწმდება. commit, რომლის შემოწმებაც ვერ მოხერხდა (git არ არის, ან ასლი ზედაპირულია — shallow, როგორც CI-ში), INCONCLUSIVE-ია და არასდროს PASS. ძველ ჟურნალს gate არ კითხულობს: ისტორია ისტორიად რჩება.

დრილს იატაკი (floor) აქვს — `gates.toml`-ში დრილის gate-ის `floor`, ანუ რამდენ შემთხვევას შეიცავს დრილი ([[ADR-0015-permission-windows-only-where-a-person-decides]]). `drill` gate ჩავარდება, თუ დრილის ბოლო ხაზში ARMED-ისა და ELSEWHERE-ის ჯამი იატაკზე ნაკლებია (შემთხვევა ამოიღეს, ან ჯგუფმა გაშვება შეწყვიტა) ან მეტია (ახალ შემთხვევასთან ერთად იატაკიც იმავე commit-ში იწევს — gate ზუსტ რიცხვს ასახელებს). ELSEWHERE ის შემთხვევაა, რომელსაც მხოლოდ სხვა სისტემა უშვებს (Windows-ის ქსელური გზები, macOS-ისა და Linux-ის ფაილის რეჟიმები და ბმულები): ის აქაც ითვლება, ამიტომ რიცხვი ყველა სისტემაზე ერთია. იატაკის დაწევა წინა commit-თან შედარებით მხოლოდ მფლობელს შეუძლია — `/approve floor N` ჟურნალში ახალ სტრიქონს წერს, რომელსაც gate კითხულობს (LEDGER); გამორთული, commit-ს მოცილებული ან წაშლილი დრილის gate იატაკს 0-მდე წევს და იმავე სტრიქონს ითხოვს; როცა მფლობელის გამორთვა უკვე წინა commit-შია, ამ gate-ზე დაწერილი იატაკი ითვლება — შემდეგი commit-ები გადის, სანამ ის უცვლელია, მისი დაწევა ან gate-ის წაშლა კი ისევ მფლობელის სტრიქონს ითხოვს. commit-ის წინ gate იატაკსაც და დრილის gate-ის ჩართულობასაც იმ `gates.toml`-იდან კითხულობს, რომელსაც commit ჩაწერს (staged ვერსია), და არა დისკიდან: თუ გაზრდილი დრილი staged-ია, აწეული იატაკი კი მხოლოდ დისკზეა, commit გაჩერდება. როცა დისკზე `drill.py` იმისგან განსხვავდება, რასაც commit ჩაწერს (ახალი შემთხვევები ჯერ staged არ არის — შეიძლება სხვა სესიისაც), დრილი არ ეშვება და commit ჩერდება (DRILL-UNSTAGED): ან `drill.py` დაამატე commit-ში (`git add`), ან, თუ მას სხვა სესია ცვლის, დაელოდე, სანამ ის თავის commit-ს გააკეთებს (L-007). guard-ი (G7) იატაკის დაწევას, წაშლასა და დრილის gate-ის გამორთვას ყოველ ცვლილებაზე ბლოკავს. ნაკრებს (kit) დისპეჩერის ჯგუფი არ აქვს, ამიტომ მისი იატაკი საკუთარია.

## ახალი gate-ის დამატება

1. `gates.toml`-ში ახალი `[[gate]]` — `builtin` (შიდა შემოწმება `gate.py`-ში) ან `cmd` (ბრძანება არგუმენტების სიად, მაგ. `["ruff", "check", "."]`; ეშვება shell-ის გარეშე, ამიტომ მასში ჩაწერილი `&` ან `;` მეორე ბრძანებას ვერ გაუშვებს; exit 0 = გავიდა, დაუყენებელი ხელსაწყო = INCONCLUSIVE).
2. `drill.py`-ში — სუფთა კონტროლი (უნდა გაიაროს) და განზრახ დეფექტი (უნდა ჩავარდეს **ამ gate-ის საკუთარი** შეტყობინებით); იმავე commit-ში დრილის `floor` ახალი შემთხვევების რაოდენობით იწევს.
