# კარიბჭეები (gates)

კარიბჭე (gate) არის მანქანური შემოწმება, რომლის შედეგზე კამათი შეუძლებელია: ან გავიდა, ან ჩავარდა, ან ვერ გაეშვა. ის არ ენდობა მოდელის სიტყვას „მუშაობს" — თავად ამოწმებს. გადაწყვეტილება: [[ADR-0006-deterministic-gates-and-evals]].

## გაშვება

```bash
py -3.12 tools/gates/gate.py                 # ყველა ჩართული gate, მთელი პროექტი
py -3.12 tools/gates/gate.py --list          # ყველა gate, გამორთულებიც, მიზეზით
py -3.12 tools/gates/gate.py --pre-commit    # რასაც .githooks/pre-commit უშვებს
py -3.12 tools/gates/gate.py --files a.md    # მხოლოდ ეს ფაილები (Stop hook ასე იყენებს)
py -3.12 tools/gates/drill.py                # ყოველი შემოწმება განზრახ ტყდება — უნდა დაიჭიროს
py -3.12 tools/gates/drill.py --self-test    # დრილის შემოწმება: stub-ებით უნდა თქვას DEAD
```

**შედეგი:** `0` — ყველა ჩართული gate გავიდა; `1` — რაღაც ჩავარდა; `2` — INCONCLUSIVE (ვერ გაეშვა, მაგ. `GITLEAKS_BIN` არარსებულ ფაილზე მიუთითებს, ან ნული ფაილი შეამოწმა). **SKIP** ნიშნავს „გამორთულია" — ეს არ არის „გავიდა", და ბოლო ხაზი ყოველთვის ამბობს, რამდენი gate-ი არ შემოწმებულა.

## სად ეშვება

- **ყოველ commit-ზე** — `.githooks/pre-commit` (`core.hooksPath = .githooks`, მხოლოდ ამ რეპოში — ამას პირველი სესიის დაწყებისას `.claude/hooks/firstrun.py` თავად რთავს). გვერდის ავლა (`--no-verify`) აკრძალულია.
- **ყოველი ტურის ბოლოს** — Stop hook ამოწმებს მხოლოდ იმ ფაილებს, რაც ამ სესიამ შეცვალა; ჩავარდნისას აგენტი აგრძელებს და ასწორებს.
- **ხელით** — ნებისმიერ დროს, ზემოთ მოცემული ბრძანებით.

## ახალი gate-ის დამატება

1. `gates.toml`-ში ახალი `[[gate]]` — `builtin` (შიდა შემოწმება `gate.py`-ში) ან `cmd` (ბრძანება არგუმენტების სიად, მაგ. `["ruff", "check", "."]`; ეშვება shell-ის გარეშე, ამიტომ მასში ჩაწერილი `&` ან `;` მეორე ბრძანებას ვერ გაუშვებს; exit 0 = გავიდა, დაუყენებელი ხელსაწყო = INCONCLUSIVE).

`secrets` gate სრულ გაშვებაზე ოთხ რამეს ამოწმებს: staged ფაილებს, შეუნახავ ცვლილებებს, ისტორიას და git-ში ჯერ არდამატებულ ფაილებს (gitleaks-ის git-რეჟიმი ამ უკანასკნელს საერთოდ ვერ ხედავს, ამიტომ თითოეული ცალკე მოწმდება). commit-ის წინ მხოლოდ staged ფაილები მოწმდება. თუ gitleaks კომპიუტერზე არ არის, იმავე ფაილებს ძრავის საკუთარი სკანერი ამოწმებს (`tools/redact.py` — იგივე სია, რომლითაც sentinel მუშაობს), და შედეგის ხაზი ამას პირდაპირ წერს: მას entropy-ის ზღვარი არ აქვს და git-ის ისტორიას არ ამოწმებს (ADR-0011).
2. `drill.py`-ში — სუფთა კონტროლი (უნდა გაიაროს) და განზრახ დეფექტი (უნდა ჩავარდეს **ამ gate-ის საკუთარი** შეტყობინებით).
3. `gates.toml` და `drill.py` დაცული ფაილებია — ცვლილებას მფლობელი ადასტურებს.
4. არასდროს: ზღვრის დაწევა ან gate-ის გამორთვა „გასამწვანებლად".
