# Lessons (loaded into every session via CLAUDE.md — keep ≤ 60 lines)

Each lesson: what happened → the rule → which machine check guards it (or "none" — then it is a backlog item).
These lessons were learned while the engine was being built (2026-09-18 … 2026-10-09); they are about the engine, the way of working and Windows, so they apply to every project made from the kit.

- **L-001 Georgian output on Windows.** Python on Windows defaults to cp1252; a hook printing Georgian died with UnicodeEncodeError and the context injection silently vanished. Rule: every script that prints reconfigures stdout/stderr to UTF-8 (and hooks run with `PYTHONUTF8=1` via `py.sh`). Guarded by: drill (episodic injection test uses Georgian).
- **L-002 SessionEnd has a 1.5 s budget.** A model summary inline in SessionEnd gets killed. Rule: slow work detaches (verified: the child survives `claude` exiting). Guarded by: drill — the stand-in model answers after 10 s; SessionEnd must return in under half that with no summary written yet, and the summary must appear later.
- **L-003 Git Bash rewrites slash arguments.** `claude -p "/approve …"` from Git Bash turned into `C:/Program Files/Git/approve`. Rule: prefix `MSYS2_ARG_CONV_EXCL='*'` when passing slash commands from bash. Not `MSYS_NO_PATHCONV=1`: it also stops the conversion of environment variables, so a POSIX path in an env var reached Python as `C:\c\Users\…` and a stray folder appeared there (2026-09-19). Guarded by: none.
- **L-004 Skill `!` injections.** They need `allowed-tools` pre-approval (headless otherwise aborts silently), do not pass through PreToolUse hooks, and do not see the `CLAUDE_PROJECT_DIR` env var — only the `${CLAUDE_PROJECT_DIR}` / `${CLAUDE_SESSION_ID}` substitutions. `'$ARGUMENTS'` is pasted as raw text, so a quote in the argument can break out; a breakout that appended a second command was refused by the permission layer (nothing ran). Keep such skills owner-only (`disable-model-invocation`) and their `allowed-tools` to one exact script. Guarded by: none (probe-verified 2026-09-18).
- **L-005 Never touch global git config** — it belongs to the person, not to the project. Configure per repo (`git config --local`). Guarded by: the project's ask rule `Bash(git config*)` — every git config change waits for the owner.
- **L-006 No Haiku for Georgian text.** It invents malformed words (2.6/5 in the eval). Use Sonnet-class or better for anything Georgian a person reads. Guarded by: none for code yet (episodic summarizer is pinned to sonnet).
- **L-007 Another session may be working in this folder.** Never commit, move or edit its files (a parallel session's prototype folder, 2026-09-18). Guarded by: Stop-gate checks only this session's touched files; guard does not cover foreign folders.
- **L-008 A shell guard must read the command the way the shell runs it.** Two critic rounds each found a plain bypass of the guard: first `env git commit -n` and `bash -c "…"`, then `echo "$(git commit -n)"` and a command on the next line. Rule: new guard patterns get a seeded case for wrappers, nested shells, substitutions and multi-line commands, not only the bare form. 2026-10-07 a probe found eighteen more: shell grammar in front of the command (`do`, `then`, `else`, `!`, `( )`, `{ }`, case branches, function bodies), `eval`, `find -exec`, and a shell fed from stdin (`echo … | bash`, `bash <<< …`, `cat <<EOF | bash`); then ECC's 160-case corpus found eight more where our parser read bash quoting differently (`foo#bar`, `$'git'`, a quoted or case `)` inside `$(…)`). Probe a new rule with these forms, and re-run a public corpus, before trusting it. Known gap: code inside an interpreter heredoc (Python, Node) is not parsed. Guarded by: drill (guard group).
- **L-009 A stub proves the stub.** The drill's summarizer ran through a stand-in, so it never noticed that the `claude` on Windows' PATH is a broken npm shim — every real auto-summary from a VS Code session would have failed. Found only by a live `claude -p` session in a copy of the project. Rule: after the drill, exercise the real binary once. Guarded by: drill (summarizer-binary cases) + live test, not automatic.
- **L-010 Real use is a test the drill cannot run.** Three days of normal use showed that VS Code opens Claude Code sessions in which nothing is said (often two in the same second); each left an empty episode — 9 files and a 7-item reconcile list of pure noise. Rule: after a new hook ships, look at what it produced after a few days of real use. An empty session (no transcript, untouched stub) now leaves no trace (the engine author's decision, 2026-09-22). Guarded by: drill (empty-session cases).
- **L-011 Two sessions in one folder share the next number and the branch.** Two parallel sessions took ADR number 0007 at the same time, and one session's commits landed on the other's branch, because the branch pointer is shared by the whole folder (2026-09-25). Rule: before writing a new numbered document, look at the folder itself, not only the index; before a commit, run `git branch --show-current`. Guarded by: none.
- **L-012 A subagent's research conclusion without a primary source does not go into a document.** A direction claimed by a research subagent turned out reversed and was caught only by an independent second check. Rule: a number or a direction comes from a primary source, or is openly marked "secondary source". Guarded by: none — a source label is documentation, not a check.
- **L-013 A new hard rule gets its test scenario in the same change.** Both review rounds found rules that had no test. Guarded by: none until the eval suite is switched on.
- **L-014 The guard over-blocks the agent's own benign commands that merely name a trigger string.** A commit message or `cat`-heredoc containing a PowerShell env-read phrase or a hook-skip flag, or a `grep` whose PATTERN names a secret file, or a `cat` or a `for` loop that merely names the approvals ledger or `approve.py` among other files, is refused (S1/B1/B2/B4) though it reads and changes nothing — the guard scans text and cannot tell a command from a description (hit three times 2026-10-07/09, five more 2026-10-11 — the last a `git add` that named the approval script). Rule: use the Grep/Edit tools instead of shell `grep`/heredoc, put such text in a `cat <<EOF` body, or reword to describe the string rather than type it; stage with `git add -u` and pass the commit message as a file (`git commit -F`). Guarded by: documented in [[ADR-0007-ai-security-and-observability]] over-block list; fail-closed by design, no check.
- **L-015 Strong-safeguard models flag defensive guard-hardening as cyber-offense.** Opus 5.5's safety filter marked a guard-hardening session of the engine `[cyber]`, killed the correctness critic mid-run and cut a response; work continued on Opus 4.8. Recurred 2026-10-11: the security critic of the idea-first phase was killed twice on Opus 5.5; re-run on Sonnet it completed. Rule: prove guard/bypass fixes with mutation tests (break-and-catch) and keep exploit payloads inside code/drill files, not in visible prose — and when a critic is blocked, the deterministic machine check is the stronger evidence anyway (ADR-0006). Guarded by: none (platform behaviour).
- **L-016 The engine is judged by a new user's journey, not by its documents.** Asked to strip a project's traces, a turn went into polishing documents; the engine author meant something else — a person installs the engine, writes an idea and is led through every stage (2026-10-11). One real session in a fresh copy with an idea as its first message showed the actual gaps in six steps for $0.39. Rule: test an engine change the way a new user meets it — a fresh copy, an idea as the first message, a real `claude -p` session (`CLAUDECODE=` and `EPISODIC_AUTOSUMMARY=0`; `EPISODIC_NESTED=1` switches the injection off). Guarded by: a live session in a fresh copy (ADR-0011; 2026-10-11: a bakery-website idea reached a specification in four turns without a setup question) — run by hand, not automatic.
- **L-017 The author's machine hides what a new user's machine lacks.** The drill passed on the author's machine because gitleaks was installed; a review found that on a machine without it four secrets cases would read DEAD (2026-10-11), and a fresh copy showed the commit checks switched off. Rule: run a new engine feature's drill groups once with the author's tools hidden — `PATH` without the tool's folder, `HOME` and `USERPROFILE` pointing at an empty folder. Hiding a tool by dropping its PATH folder also drops whatever shares that folder (Scoop's shims, Homebrew's bin, /usr/bin) — inside the drill, swap the one function that searches for it instead. Guarded by: drill — its own gitleaks search decides which scanner the secrets cases expect, so the same drill passes on both kinds of machine and catches a silent fallback; the whole-drill run with the author's tools hidden is manual.
