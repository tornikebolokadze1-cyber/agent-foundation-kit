# L-026 — A graph error in a file you may not edit does not stop your work

**What happened.** On 2026-11-08 the session brief showed one graph error: a compact summary copied verbatim into
another session's episode linked an auto-memory file that lives outside the repository.
The engine author said „კი, გაასწორე", but the guard's G3 refused the edit (another session's episode), and a message asking
that session to make it was refused as well. The ADR-0018 commit was then reported as blocked — wrongly: the parallel
session had committed three times after the error appeared at 11:28, and at commit the
gates read the git index exported to a temporary folder, never the working copy (`tools/gates/gate.py`: the docstring
and `run()`). The next commit then passed with ten gates green and the error still on disk.

**Where the line is.** Staging `progress.md` while its hook-written log held links to two uncommitted episodes failed
the commit's graph gate (`LINK-BROKEN`, exit 1). The parallel session had already committed `progress.md` without those
entries by staging a stripped copy — `git hash-object -w` of the wanted text, then
`git update-index --cacheinfo 100644,<sha>,progress.md`; the working copy keeps the entries.

**Guard.** None yet for the brief: marking such an error as not this session's to fix is an open proposal. The root
cause — a copied summary may carry a link that does not resolve — is fixed since 2026-11-08: such a link is written as
code (`context_graph.unlink_unresolved`).

The rule is this lesson's line in [[LESSONS]].
