# L-028 — A probe's flag can create what it measures

**What happened.** The 2026-11-09 audit reported that a command runs through the PowerShell tool past the ask list,
as if any session had that tool. Its five probes all passed `--allowedTools "Bash" "PowerShell"`, so that the session
would not stop at a permission question — and that flag is one of the two things that switch the tool on. Without it
the tool was not offered at all. The finding was true only for a session in which someone had switched the tool on;
the report said more than was measured, and the engine author was told that a hole was open which was closed by default.

**How it was found.** While the fix was being written, Claude Code's tools reference said that PowerShell is turned
off when a settings file holds a Bash deny rule. A second probe then changed one thing per run and read the init
event's tool list: `--allowedTools Bash` and no switch — not offered; the switch — offered; the flag — offered
(the first probe's record was corrected afterwards).

**What to do.** A live probe first reads what is there with nothing passed for it — the init event's tool list costs
one short session — and only then changes one thing per run. A flag that grants a tool a permission
(`--allowedTools X`) is part of the experiment, never neutral plumbing. A claim goes into a report together with the
conditions it was measured under.

**Guard.** None.
