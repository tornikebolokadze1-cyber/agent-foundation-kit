# L-008 — A shell guard must read the command the way the shell runs it

**What happened.** Two critic rounds each found a plain way past the guard: first a wrapper in front of the command and
a nested shell, then a command substitution and a command on the next line. On 2026-10-07 a probe found eighteen more:
shell grammar in front of the command (loop and condition keywords, negation, subshells and groups, case branches,
function bodies), `eval`, `find -exec`, and a shell fed from stdin (a pipe, a here-string, a here-document). Then ECC's
160-case public corpus found eight more where our parser read bash quoting differently (a hash inside a word, ANSI-C
quoting, a quoted or case parenthesis inside a substitution).

**A new reader can drop an old catch.** On 2026-10-19 masking a substitution as one word hid a hook-skip flag produced
by a substitution, which the old word split had blocked by accident. Neither the corpus nor the drill had that form;
running the old and the new guard side by side on probe forms found it.

**What to probe.** Every form named above, the bare form, and a public corpus — before trusting a new rule. The forms
themselves live in the drill's `guard` group, not in prose (L-015).

**Known gap.** Code inside an interpreter heredoc (Python, Node) is not parsed.
