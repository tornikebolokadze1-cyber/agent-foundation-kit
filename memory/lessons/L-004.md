# L-004 — Skill `!` injections

**What happened.** A skill's `!` line needs `allowed-tools` pre-approval (headless otherwise aborts silently), does not
pass through PreToolUse hooks, and does not see the `CLAUDE_PROJECT_DIR` env var — only the `${CLAUDE_PROJECT_DIR}` /
`${CLAUDE_SESSION_ID}` substitutions. `'$ARGUMENTS'` is pasted as raw text, so a quote in the argument can break out; a
breakout that appended a second command was refused by the permission layer (nothing ran). Hence such skills stay
owner-only (`disable-model-invocation`) with their `allowed-tools` narrowed to one exact script.

**The quoted path.** The injected path is quoted, so a pattern that names the script and its argument together
(`*episodic.py status*`) never matches `…episodic.py" status` — `*episodic.py* status*` does (probe 2026-10-13;
the engine's own `/session-close` and `/orchestrate` patterns still carry this defect — their fix waits for the
engine author's yes).

**Ask list first.** A skill's `allowed-tools` does not carry a `!` line past the project's ask list (probe 2026-11-08,
Claude Code 2.1.319, fresh clones with `--setting-sources project,local`): with `Bash(git config*)` on the ask
list, a skill pre-approving `Bash(git config *)` was stopped — "Claude requested permissions to use Bash, but you
haven't granted it yet" — from the slash command and when the model invoked it with the Skill tool, while the mutant
without that rule ran it both ways. The deny list holds the same way (`Bash(git commit -n*)` — "Permission to use Bash
with command … has been denied"; its mutant ran the line), and auto mode changes neither (`--permission-mode auto`: both
lines stopped, the ask rule's mutant ran) — there the ask rule also stopped the model's own Bash call, which ran in its
mutant. Measured in `claude -p`, where nobody can answer an ask: the probe shows the rule takes effect, not the window a
person would see. So G9 leaves ask- and deny-listed commands to Claude Code; no machine check guards this platform
behaviour — probe again after a Claude Code update that touches permissions.

**Guard.** Probe-verified 2026-09-18 and 2026-10-13. Since 2026-11-08 the guard's G9 reads a skill's or slash command's
`!` lines and `allowed-tools` when the file is written and refuses one it would refuse as a command (drill
`guard` group); the other points have no check.

The rule is this lesson's line in [[LESSONS]].
