# სპეციფიკაციები (specs)

სპეციფიკაცია აღწერს ერთ ფუნქციას ისე, რომ მისი შემოწმება მანქანურად შეიძლებოდეს: რა პრობლემას წყვეტს (რომელ მიზანს — G1, G2… [[intent]]-დან), რა შედის და რა არა, მოთხოვნები (REQ-NNN) და მიღების კრიტერიუმები (Given / When / Then), რომელთაგან თითოეული ასახელებს gate-ს ან eval-ს, რომელიც მას დაამტკიცებს.

**ცხოვრების ციკლი:** `/spec` ქმნის `SPEC-NNNN-slug.md`-ს სტატუსით `draft` → შევსების შემდეგ `review` → `spec-reviewer` subagent-ი ამოწმებს → მფლობელი: `/approve spec NNNN` (`approved`). დამტკიცება შესაძლებელია მხოლოდ მაშინ, როცა `intent.md` უკვე `accepted`-ია. გეგმა (`/feature-plan`) მხოლოდ დამტკიცებულ სპეციფიკაციაზე იწერება. შეცვლა: ჯერ ხელახლა გახსნა (მხოლოდ `status: draft`), მერე რედაქტირება და ხელახალი დამტკიცება; მთლიანად ახალი ვერსია — ახალი ფაილი ველით `supersedes`.
