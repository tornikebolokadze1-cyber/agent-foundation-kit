# ვებსაიტის პროექტის სახელმძღვანელო

ეს სახელმძღვანელო ეხება პროექტებს, რომლებიც ბრაუზერში იხსნება და ძირითადად ინფორმაციას აჩვენებს: ერთგვერდიან საიტს (landing page — გვერდი, რომელიც პროდუქტს ან მომსახურებას წარადგენს), მცირე ბიზნესის საიტს (საცხობი, სალონი, კლინიკა), პორტფოლიოს, ბლოგს და პატარა მაღაზიას, რომელიც შეკვეთებს ან მოთხოვნებს იღებს. როცა საიტს ანგარიშები (შესვლა, რეგისტრაცია), ონლაინ გადახდა ან მომხმარებლების მონაცემთა ბაზა სჭირდება, ის უკვე ვებ-აპლიკაციაა: უთხარი ადამიანს ეს პირდაპირ, პირველ ვერსიაში ნუ ჩასვამ და დაყავი ეტაპებად (staged scope) — ჯერ ამ სახელმძღვანელოს მიხედვით საიტი, მერე თითო ახალი შესაძლებლობა ცალკე `/spec`-ით, ხოლო ის, რაც საიდუმლო გასაღებს ან ფულს ეხება, ცალკე `/adr`-ით და მხოლოდ ადამიანის „კი“-თ. თუ პროექტი საერთოდ საიტი არ არის (ბოტი, ავტომატიზაცია, თამაში, მონაცემთა ინსტრუმენტი) ან უკვე სრული ვებ-აპლიკაციაა, გამოიყენე `docs/guides/other.md`. ეტაპების ნომრები [[ADR-0011-idea-first-stage-conductor]]-ის მიხედვითაა.

## 1. ინტერვიუ — რა ვკითხოთ (ეტაპი 1)

კითხვები სათითაოდ დასვი (ასეთია `/intent`-ის წესი); რაზეც იდეამ უკვე უპასუხა, ის გამოტოვე. ვარიანტები მარტივი სიტყვებით ჩამოაყალიბე, რეკომენდაციას კი მიზეზიც დაურთე. ისარი (→) გიჩვენებს, `intent.md`-ის რომელ ნაწილში ჩაიწერება პასუხი: მიზანი (§2, G-ნომრითა და გაზომვის ხერხით), ვისთვის (§3), „რას არ ვაკეთებთ“ (§4) ან შეზღუდვა (§5). ბიზნესის ფაქტები (ფასი, საათი, მისამართი, ნომერი) ჩაწერე `docs/domain/`-ში თარიღითა და წყაროთი (წყარო: მფლობელი); საიტის ტექსტი მათგან აიღე, შენი ვარაუდი კი ჰიპოთეზად მონიშნე.

1. **მთავარი მოქმედება.** „სტუმარმა საიტზე რა უნდა გააკეთოს?“ — (ა) დარეკოს ან მოგწეროს; (ბ) შეუკვეთოს ან დაჯავშნოს; (გ) უბრალოდ ნახოს და წაიკითხოს (პორტფოლიო, ბლოგი). რეკომენდაცია: ერთი მთავარი მოქმედება — მისით ვზომავთ, გამოვიდა თუ არა საიტი. → მიზანი G1 (გაზომვა: მთავარი ღილაკი ტელეფონზე პირველ ეკრანზე ჩანს).
2. **ვინ და რით შემოდის.** „ვინ უნდა ნახოს საიტი და რომელი მოწყობილობიდან?“ — (ა) ძირითადად ადგილობრივები, ტელეფონით; (ბ) ტურისტებიც; (გ) პროფესიონალები, კომპიუტერით. რეკომენდაცია: დიზაინი ტელეფონის ეკრანით დაიწყე — პატარა ბიზნესის სტუმარი ხშირად ტელეფონით შემოდის; ადამიანი თუ სხვას იტყვის, მას დაუჯერე. → ვისთვის (§3); „ჯერ ტელეფონზე“ — შეზღუდვა (§5).
3. **კონტაქტი, შეკვეთა და ფული** (თუ პირველ კითხვაზე (ა) ან (ბ) აირჩია). „როგორ დაგიკავშირდებიან ან შეგიკვეთავენ?“ — (ა) ტელეფონით და მესენჯერის ბმულით (WhatsApp, Viber, Messenger) — საიტი არაფერს ინახავს; (ბ) ფორმით, რომელიც მოთხოვნას ელფოსტით გამოგიგზავნის (ამას ფორმის მიმღები სერვისი აკეთებს, მაგ. Formspree ან Netlify Forms); (გ) კალათითა და ონლაინ გადახდით. რეკომენდაცია: (ა) — პერსონალურ მონაცემებს, სპამსა და ფულს საიტი არ ეხება; (ბ) მეორე ვერსიაში დაემატება, (გ) უკვე ვებ-აპლიკაციაა. → მიზანი (დაკავშირების გზა) და „რას არ ვაკეთებთ“ (გადახდა გადაიდო); ფულისა და ვალდებულების საკითხს ადამიანი წყვეტს.
4. **გვერდები.** „რა გვერდები გჭირდება?“ — (ა) ერთი გრძელი გვერდი (ჩვენ შესახებ, მენიუ ან მომსახურება, კონტაქტი); (ბ) 3–5 გვერდი; (გ) ბლოგი ან კატალოგი ბევრი ჩანაწერით. რეკომენდაცია: (ა) — შედეგი სწრაფად ჩანს და მერე გაფართოება ადვილია. → მიზანი G2; დანარჩენი — „რას არ ვაკეთებთ“ (§4).
5. **ტექსტები და ფოტოები.** „გაქვს მზა ტექსტები და საკუთარი ფოტოები?“ — (ა) ორივე მაქვს; (ბ) ფოტოები მაქვს, ტექსტს ჩემი სიტყვებით დაწერს Claude; (გ) არცერთი მაქვს. რეკომენდაცია: (ბ) — Claude წერს, ადამიანი ასწორებს, რადგან საიტზე გამოგონილი ფაქტი ყველაზე ძვირი შეცდომაა. → შეზღუდვა (§5): ფაქტებისა და ფოტოების წყარო მხოლოდ მფლობელია.
6. **ენა.** „რომელ ენაზე უნდა იყოს საიტი?“ — (ა) მხოლოდ ქართულად; (ბ) ქართულად და ინგლისურად; (გ) სამ ან მეტ ენაზე. რეკომენდაცია: (ა) პირველ ვერსიაში, მეორე ენა — ცალკე შესაძლებლობად: ყოველი დამატებითი ენა დასაწერ და გადასამოწმებელ ტექსტს ზრდის. → შეზღუდვა (§5); გადადებული ენა — „რას არ ვაკეთებთ“ (§4).
7. **იერსახე.** „გაქვს ლოგო და ფერები? რომელი საიტი მოგწონს და რომელი — არა?“ — (ა) მაქვს ლოგო და ფერები; (ბ) მაქვს ერთი-ორი მისაბაძი საიტი; (გ) არაფერი მაქვს. რეკომენდაცია: (ბ) — მაგალითი გემოვნებას სიტყვებზე უკეთ გადმოსცემს; (გ)-ს შემთხვევაში ორი განსხვავებული მიმართულება შესთავაზე. → შეზღუდვა (§5), თუ ბრენდის ფერები არსებობს; დანარჩენი სპეციფიკაციაში შევა.
8. **მონაცემები და კანონი.** „საიტი ვინმეს მონაცემებს აგროვებს — ფორმით, სტატისტიკით, ქუქიებით (cookies — ბრაუზერში შენახული პატარა ჩანაწერები)?“ — (ა) არა, მხოლოდ ინფორმაციას აჩვენებს; (ბ) მხოლოდ ფორმის მონაცემებს; (გ) სტატისტიკასაც ან რეკლამის პიქსელსაც. რეკომენდაცია: (ა) პირველ ვერსიაში. კანონის მოთხოვნებს (პერსონალური მონაცემების დაცვა) ადამიანი ოფიციალურ წყაროში ამოწმებს — იურიდიულ დასკვნას Claude არ იძლევა. → შეზღუდვა (§5).
9. **მისამართი, ვადა, ბიუჯეტი.** „რა მისამართზე გინდა საიტი, რა ვადაში და რა ბიუჯეტით?“ — (ა) მაქვს დომენი (საიტის საკუთარი სახელი, მაგ. mybakery.ge); (ბ) ჯერ ჰოსტინგის (ადგილი, სადაც საიტი ინტერნეტში დგას) უფასო მისამართით დავიწყოთ; (გ) დომენი ახლავე უნდა ვიყიდო. რეკომენდაცია: (ბ) — საკუთარ დომენს შედეგის მოწონების შემდეგ მივაბამთ, რადგან ის განმეორებადი ხარჯია და საიტის ხარისხზე არ მოქმედებს. → შეზღუდვა (§5): ბიუჯეტი, ვადა.

**თვალით არჩევა (ინტერვიუს ბოლოს — მშენებლის შემოწმებამდე და სპეციფიკაციამდე).** იერსახეს ადამიანი სიტყვებით იშვიათად აღწერს, დანახვისას კი მაშინვე იცის, რა მოსწონს. ამიტომ ჩატში აჩვენე 2–3 განლაგება ASCII-ნახატად (ტექსტის სიმბოლოებით დახატული სქემა ტელეფონის ეკრანისთვის: სად დგას სახელი, ფოტო, მთავარი ღილაკი და მენიუ) და დასახელებული პალიტრა — 4–6 ფერი, თითო სახელითა და კოდით (მაგ. „ფქვილისფერი #F5EFE6“), და ჰკითხე, რომელი უფრო ახლოსაა მის აზრთან. ერთი განლაგება ასე შეიძლება გამოიყურებოდეს:

```
+------------------------+
| ლოგო           მენიუ ≡ |
| [     დიდი ფოტო      ] |
| ერთი წინადადება ჩვენზე |
| [  დარეკვა / ჯავშანი ] |
| საათი · მისამართი      |
+------------------------+
```

არჩეული ჩაწერე `intent.md`-ის §5-ში (წყარო: **მფლობელი**, თარიღით) — იქიდან სპეციფიკაცია აიღებს. ერთფაილიანი საცდელი გვერდი (ერთი HTML ფაილი, რომელიც ბრაუზერში იხსნება) მხოლოდ ადამიანის „კი“-თ კეთდება და პროექტის საქაღალდის გარეთ, დროებით საქაღალდეში (`${TMPDIR:-/tmp}`); ადამიანს ფაილის სრული ბილიკი უთხარი. ეს ესკიზია და არა პროექტის კოდი: commit-ში არ ხვდება, აშენება კი მაინც მე-4 ეტაპზე იწყება.

## 2. რით ავაშენოთ — სტეკის ვარიანტები (ეტაპი 3)

Python-ის ვარიანტში ჯერ პროექტის საკუთარი ვირტუალური გარემო (virtual environment — ამ პროექტის პაკეტების ცალკე საქაღალდე, რომ ადამიანის სხვა პროექტებსა და ძრავას არ შეეხოს) შექმენი: `bash .claude/hooks/py.sh -m venv .venv` (`.venv` უკვე `.gitignore`-შია და გრაფი მას გამოტოვებს); Ubuntu-სა და Debian-ზე venv-ის შესაქმნელად ჯერ `sudo apt install python3.12-venv` უნდა დაყენდეს (ადამიანის „კი“-თ). მერე ყოველი დაყენება და გაშვება `{venv_python}`-ით კეთდება: `{venv_python}` — Windows-ზე `.venv/Scripts/python`, macOS-სა და Linux-ზე `.venv/bin/python`; `tools/gates/gates.toml`-ში ზუსტად ასე იწერება და `gate.py` თავად ცვლის. სტანდარტული ბიბლიოთეკის ერთჯერადი ბრძანებები (`bash .claude/hooks/py.sh -m http.server`) და ძრავის საკუთარი ბრძანებები (`bash .claude/hooks/py.sh tools/…`) უცვლელია.

შესთავაზე ორი-სამი ვარიანტი, ერთი რეკომენდაციით. ფასი და ლიმიტი არჩევისას ოფიციალურ გვერდზე შეამოწმე — აქ მხოლოდ კატეგორიებია. სამივე ვარიანტი სტატიკურ საიტს (ფაილები, რომლებსაც სერვერზე საკუთარი ლოგიკა არ სჭირდება) აგებს, ამიტომ ჰოსტინგიც ერთნაირია: GitHub Pages, Netlify ან Cloudflare-ის სტატიკური ჰოსტინგი — სამივე ჰოსტინგს უფასო ტარიფი აქვს; დომენი კი ფასიანია (წლიური გადასახადი). საიტი ცალკე საქაღალდეში, `site/`-ში დადე, რომ პროექტის დოკუმენტებს არ აერიოს; Node-ის ვარიანტებში ბრძანებები ამ საქაღალდეშია გასაშვები. ბრძანებები სამივე სისტემისთვისაა დაწერილი (Windows 10/11-ზე — Git Bash-ში, macOS-სა და Linux-ზე — ჩვეულებრივ ტერმინალში), სისტემაზე დამოკიდებული ადგილები კი სამივე ვარიანტითაა მითითებული. ყოველი დაყენება (pip, Node, npm-ის პაკეტი) ადამიანის „კი“-ა; Node (JavaScript-ის გასაშვები გარემო) ოფიციალური ინსტალერით ან სისტემის პაკეტების მმართველით დგება: Windows-ზე `winget install OpenJS.NodeJS.LTS`-ით, macOS-ზე `brew install node`-ით, Linux-ზე `sudo apt install nodejs npm`-ით (ან დისტრიბუტივის საკუთარი პაკეტებით); ახალი PATH (სია, საიდანაც ტერმინალი პროგრამებს პოულობს) კი მხოლოდ ახლად გახსნილ ტერმინალში ჩანს. ცხრილებში ხუთი ბრძანებაა: install (დაყენება), run (local — ადგილობრივად გაშვება), lint (კოდის ავტომატური შემოწმება ტიპურ შეცდომებზე), test (ავტომატური ტესტები) და show (როგორ ხედავს ადამიანი შედეგს).

**ა) უბრალო HTML, CSS და JavaScript — „რეკომენდაცია დამწყებისთვის“.**
- რა არის: ხელით დაწერილი ფაილები — HTML (გვერდის შინაარსი), CSS (იერსახე) და JavaScript (ქცევა) — აგების (build — ფაილების გამოსაქვეყნებლად მომზადება) ეტაპის გარეშე.
- გამოდგება: ერთგვერდიანი საიტისთვის, მცირე ბიზნესისა და პორტფოლიოსთვის, პატარა კატალოგისთვის, სადაც შეკვეთა ტელეფონით ან მესენჯერით ხდება.
- ხარჯი: ხელსაწყოები უფასოა; ჰოსტინგს უფასო ტარიფი აქვს. ჰოსტინგი: `site/` საქაღალდე სტატიკურ ჰოსტინგზე.
- რატომ დამწყებისთვის: Node არ სჭირდება, ნაკლები რამ ფუჭდება, ადამიანიც ხედავს ფაილებს და ნომერს ან საათს ხელითაც შეცვლის.

| ნაბიჯი | ბრძანება |
|---|---|
| install | `{venv_python} -m pip install pytest djlint` (მხოლოდ შემოწმების ხელსაწყოები; თავად საიტს არაფერი სჭირდება) |
| run (local) | `bash .claude/hooks/py.sh -m http.server 8000 --bind 127.0.0.1 --directory site` |

სტეკის ADR-ში (`/adr`) ჩაიწერება არჩეული ვარიანტის ეს ხუთი ბრძანება, ჰოსტინგი და საქაღალდე. მე-4 ეტაპის დასაწყისში `tools/gates/gates.toml`-ში `lint` და `unit` gate-ები (მანქანური შემოწმებები) ამავე ბრძანებებით ირთვება (`enabled = true`, `cmd` კი არგუმენტების სიაა, მაგ. `["{venv_python}", "-m", "djlint", "site", "--lint"]`) — ადამიანის „კი“-თ, რადგან gates.toml დაცული ფაილია. გაითვალისწინე:
- მე-3 ეტაპზე კოდი ჯერ არ არსებობს, ამიტომ ADR-ში ბრძანებები ჩაიწერება როგორც „ჯერ გაუშვებელი“; გეგმის პირველი ამოცანა თითოეულს ერთხელ უშვებს, და თუ რომელიმე სხვაგვარი აღმოჩნდა, ცვლილება გეგმის `## გადახრები`-ში იწერება (დამტკიცებული ADR უცვლელი რჩება).
- gate-ები პროექტის ძირეული საქაღალდიდან და shell-ის გარეშე ეშვება, ამიტომ `site/`-ის Node-სკრიპტებისთვის `cmd = ["npm", "--prefix", "site", "run", "lint"]`; `package.json`-ში დაამატე, რაც აკლია: სკრიპტი `lint` (Astro-ში — `astro check`) და `test` (`vitest run`).
- `unit` პირველ ტესტთან ერთად ჩართე: ცარიელ ნაკრებზე ტესტების გამშვები შეცდომით ასრულებს მუშაობას (pytest გასვლის კოდად 5-ს აბრუნებს).
- ჩართვის შემდეგ ერთხელ განზრახ გააფუჭე ის, რასაც gate ამოწმებს (მაგ. ტესტში არასწორი მოსალოდნელი შედეგი ჩაწერე), და დარწმუნდი, რომ gate წითლდება; მერე გაასწორე — სხვაგვარად არ იცი, შეუძლია თუ არა მას ჩავარდნა.
- Node-ის ვარიანტებში `site/`-ს თავისი `package.json` აქვს, ამიტომ ძრავის გრაფი მას პროდუქტის კოდად თვლის: მის Markdown-ფაილებსა და `node_modules`-ს არ ამოწმებს (ADR-0011 §7). scaffold-ის შემდეგ მაინც გაუშვი `bash .claude/hooks/py.sh tools/context_graph.py check` — შედეგი `errors=0` უნდა იყოს.

## 3. პირველი ვერსია — რა შედის და რა არა (ეტაპი 2 და 4)

- **შედის** (სპეციფიკაციაში `REQ-NNN`-ებად ჩაიწერება): ერთი გვერდი ან 3–5 მოკლე გვერდი; პირველ ეკრანზე სახელი, ერთი წინადადება იმაზე, რას აკეთებს ბიზნესი, და მთავარი მოქმედების ღილაკი (დარეკვა, მესენჯერი ან ჯავშანი); მფლობელის დადასტურებული ფაქტები (მენიუ ან მომსახურება, ფასები, სამუშაო საათები, მისამართი, რუკის ბმული); 3–6 ფოტო, ვებისთვის შემცირებული; ტელეფონზეც და კომპიუტერზეც კარგად ჩანს; გვერდის სათაური და მოკლე აღწერა (ძიებისა და გაზიარებისთვის); ერთი ენა.
- **გადაიდება** (ჩაწერე `intent.md`-ის §4-ში „რას არ ვაკეთებთ“ და `plan.md`-ის backlog-ში, რომ არ დაიკარგოს): ანგარიშები და შესვლა, ონლაინ გადახდა და კალათა, ბლოგი და ტექსტის რედაქტირების პანელი, მეორე ენა, ანიმაციები, სტატისტიკა და ქუქიები, ჩათი, კომენტარები, სიახლეების გამოწერა.

მიღების კრიტერიუმების მაგალითები (Given / When / Then; ქვემოთ უბრალო HTML-ის ხელსაწყოებია, Astro-სა და Vite-ში იგივე შემოწმებებს `vitest` ასრულებს; მფლობელის პასუხებზე მოარგე):
- AC-001 — Given ტელეფონის სიგანე (375 px), When იხსნება მთავარი გვერდი, Then მთავარი მოქმედების ღილაკი პირველ ეკრანზე ჩანს და ჰორიზონტალური გადახვევა არ ჩნდება. ამტკიცებს: ეკრანის სურათი 375×812-ზე და ადამიანის თვალი (ეტაპი 5).
- AC-002 — Given ნებისმიერი გვერდის HTML, When ტესტი მას კითხულობს, Then ზუსტად ერთი `<h1>` არის, ყველა `<img>`-ს არაცარიელი `alt` აქვს და გვერდს `<html lang="ka">` და `<meta charset="utf-8">` აქვს. ამტკიცებს: pytest (`unit`) და `djlint --lint` (`lint`).
- AC-003 — Given მფლობელის დასახელებული ტელეფონის ნომერი (`docs/domain/`, წყარო: მფლობელი), When სტუმარი „დარეკვის“ ბმულს ეხება, Then `tel:` ბმული ზუსტად ამ ნომერს შეიცავს. ამტკიცებს: pytest (`unit`).
- AC-004 — Given საიტის ყველა გვერდი, When ტესტი შიდა ბმულებს გადაუყვება, Then არცერთი ბმული არარსებულ გვერდს ან ფაილს არ უთითებს. ამტკიცებს: pytest (`unit`).
- AC-005 — Given მფლობელის დადასტურებული ფასების სია (`docs/domain/`), When ტესტი გვერდების ფასებს კითხულობს, Then გვერდზე არცერთი ფასი არ არის, რომელიც ამ სიაში არ წერია. ამტკიცებს: pytest (`unit`) და მფლობელის თვალი მე-5 ეტაპზე.

## 4. როგორ ვაჩვენოთ შედეგი (ეტაპი 5)

ადამიანი კოდს არ კითხულობს, ამიტომ აჩვენე მუშა საიტი და უთხარი ზუსტად, სად გახსნას და რა ნახოს. ქვემოთ მისამართად `127.0.0.1:8000` წერია; Astro-სა და Vite-ში ბრძანების დაბეჭდილი მისამართი აიღე.
1. ჯერ თავად გაუშვი `bash .claude/hooks/py.sh tools/gates/gate.py` (უნდა დასრულდეს exit 0-ით) და არჩეული სტეკის ხუთივე ბრძანება; წითელი შედეგი ადამიანს ნუ აჩვენებ.
2. სერვერი ფონურ რეჟიმში გაუშვი (Astro-სა და Vite-ში ჯერ `npm run build`, მერე `npm run preview`) და შეამოწმე: `curl -s http://127.0.0.1:8000` უნდა დააბრუნოს შენი გვერდის HTML (მარტო წარმატებული პასუხი საკმარისი არ არის: იმავე პორტზე სხვა პროგრამაც შეიძლება პასუხობდეს). თუ პორტი დაკავებულია, სხვა აირჩიე.
3. უთხარი ადამიანს: „გახსენი ბრაუზერში `http://127.0.0.1:8000`. პირველ ეკრანზე უნდა ჩანდეს სახელი, ფოტო და მთავარი ღილაკი. გადაახვიე ბოლომდე, დააჭირე ღილაკს და მენიუს ყველა ბმულს, მერე შეამოწმე ყოველი ფაქტი — ფასი, საათი, მისამართი, ნომერი: სიმართლე მხოლოდ შენ იცი.“
4. ტელეფონის ხედი ორნაირად: ბრაუზერში F12 (macOS-ზე Cmd+Option+I), მერე ტელეფონის ხატულა (Ctrl+Shift+M, macOS-ზე Cmd+Shift+M) — ამას ადამიანი თავად ნახავს; შენ კი გადაიღე ეკრანის ორი სურათი Playwright CLI-ით: `{venv_python} -m playwright screenshot --viewport-size=1440,900 http://127.0.0.1:8000 "${TMPDIR:-/tmp}/desktop.png"` (კომპიუტერი) და იგივე ბრძანება `--viewport-size=375,812`-ით და ფაილით `"${TMPDIR:-/tmp}/phone.png"` (ტელეფონი); Node-ის ვარიანტებში `npx playwright …` იგივე არგუმენტებით. თუ Playwright არ არის დაყენებული, `{venv_python} -m pip install playwright`, შემდეგ ბრაუზერისთვის `{venv_python} -m playwright install chromium` (ორივე ადამიანის „კი“-ა; Playwright-ის განახლების შემდეგ ბრაუზერის ხელახლა დაყენებაც შეიძლება საჭირო გახდეს). სურათები პროექტის გარეთ, დროებით საქაღალდეში (`${TMPDIR:-/tmp}`) დატოვე და ადამიანს ფაილის ბილიკი უთხარი.
5. ჩავარდნა ასე გამოიყურება: ბრაუზერი ამბობს, რომ საიტს ვერ უკავშირდება (სერვერი არ მუშაობს ან პორტი სხვაა); გვერდი ცარიელია ან 404-ს აჩვენებს (არასწორი საქაღალდე); ქართული ასოები უცნაურ ნიშნებად ან კვადრატებად ჩანს (`<meta charset="utf-8">` აკლია ან შრიფტს ქართული ასოები არ აქვს); ტელეფონზე ჰორიზონტალური გადახვევა ჩნდება; ფოტო გატეხილი ხატულით ჩანს; ღილაკი არაფერს აკეთებს; ცვლილება არ ჩანს (ბრაუზერი ძველ ასლს აჩვენებს — Ctrl+F5, macOS-ზე Cmd+Shift+R). ასეთი რამ ჯერ გაასწორე და მერე აჩვენე.
6. ბოლოს ერთი კითხვა: „ეს არის ის, რაც გინდოდა?“ და პირდაპირ დაწერე, რა არ შეგიმოწმებია (ნამდვილი ტელეფონი, სხვა ბრაუზერი, გამოქვეყნებული მისამართი). სერვერი ჩართული დატოვე, სანამ ადამიანი საიტს ათვალიერებს; როცა იტყვის, რომ ნახა, ან სესიის დასრულებამდე, გააჩერე და `curl`-ით შეამოწმე, რომ მისამართი აღარ პასუხობს — „გავაჩერე“ მხოლოდ ამის შემდეგ თქვი. თუ ადამიანი მოგვიანებით დაბრუნდება, სერვერი ხელახლა გაუშვი.
7. გამოქვეყნება (`git push` და ჰოსტინგთან დაკავშირება) ცალკე ნაბიჯია, ადამიანის „კი“-თ. ჰოსტინგის ანგარიშს ადამიანი თავად ხსნის: უთხარი, რისთვის სჭირდება, რა ღირს (უფასო ტარიფის ზღვარი და ითხოვს თუ არა ბარათს — ოფიციალურ გვერდზე გადაამოწმე, თორემ თქვი „გადასამოწმებელია“), რამდენიმე ნაბიჯით როგორ გახსნას და რა მოგწეროს უკან (მაგალითად „მზადაა“ ან საიტის მისამართი); პაროლი, კოდი ან გასაღები ჩატში არასოდეს — გასაღები, თუ საჭიროა, მხოლოდ `.env`-ში. სანამ ანგარიში არ აქვს, საიტი ლოკალურად მზადაა და ეს ნაბიჯი უბრალოდ ელოდება. გამოქვეყნების შემდეგ ცოცხალი მისამართი `curl -s <მისამართი>`-ით გადაამოწმე (შენი გვერდი უნდა დაბრუნდეს) და სთხოვე ორ-სამ რეალურ ადამიანს (თანამშრომელი, ერთგული კლიენტი), ტელეფონიდან გახსნან — ეს არის პილოტი; მათი შენიშვნა ახალი `/spec`-ია.

## 5. ხაფანგები და უსაფრთხოება

ყოველ პუნქტში „შენ:“-ის შემდეგ წერია, რა გააკეთო.
1. **საიდუმლო მხოლოდ `.env`-ში.** ბრაუზერისთვის გაგზავნილი ყველა ფაილი (HTML, CSS, JavaScript) საჯაროა, ამიტომ გასაღები (ფორმის სერვისის, რუკის, ელფოსტის) საიტის კოდში არასდროს უნდა მოხვდეს. შენ: `.env`-ს არც კითხულობ, არც წერ; ცვლადის სახელი და ნიმუში `.env.example`-ს ბოლოში დაუმატე (ფაილი პროექტში უკვე არსებობს — თავიდან ნუ დაწერ), ნამდვილ მნიშვნელობას ადამიანი ჩასვამს. თუ ფუნქციას საიდუმლო გასაღები სჭირდება, ის უკვე სერვერის საქმეა — გაჩერდი და `/adr` შესთავაზე (ფორმის სერვისის საჯარო მისამართი მისაღებია, საიდუმლო გასაღები — არა).
2. **პერსონალური მონაცემები.** რაც არ გჭირდება, ნუ აგროვებ (სახელი და ტელეფონი ხშირად საკმარისია); პირადი ტელეფონი ან მისამართი საიტზე ყველასთვის ხილულია. შენ: ჰკითხე, ვინ ნახავს ფორმის მონაცემს და სად ინახება; საჯარო ნომერი ადამიანს დაადასტურებინე; იურიდიულ დასკვნას ნუ იძლევი.
3. **სპამი.** ღია ფორმასა და ტექსტად დაწერილ ელფოსტის მისამართს ბოტები პოულობენ. შენ: ფორმას უხილავი ველი (honeypot), რომელსაც მხოლოდ ბოტი ავსებს, ან ფორმის სერვისის ჩაშენებული დაცვა დაუმატე; პირველ ვერსიაში ტელეფონი და მესენჯერის ბმული უფრო უსაფრთხოა.
4. **ფოტოები და ლიცენზია.** სხვის ფოტოს (Google, Facebook, კონკურენტი) არ ვიყენებთ; ადამიანების სახეებს თანხმობა სჭირდება; AI-ით შექმნილი სურათი პროდუქტად (საცხობის ტორტი, რომელიც არ არსებობს) სტუმარს ატყუებს. შენ: გამოიყენე მფლობელის საკუთარი ან ლიცენზირებული ფოტო (ლიცენზიის პირობები იმ დღეს გადაამოწმე); ფოტოები ვებისთვის შეამცირე — ტელეფონის ორიგინალი ხშირად რამდენიმე მეგაბაიტია და საიტს ანელებს.
5. **გამოგონილი შინაარსი.** ფასი, საათი, მისამართი, ნომერი, ჯილდო, გამოხმაურება მხოლოდ მფლობელისგან მოდის, მოდელი კი ზოგჯერ ტექსტს ზედმეტ ფაქტებს უმატებს. შენ: საიტის ქართულ ტექსტს Sonnet-ის კლასის ან უკეთესი მოდელი წერს, Haiku — არასდროს (L-006), და ფაქტ-ფაქტ ადარებ ადამიანის თქმულს; შეფასებას, ჯილდოს ან სამედიცინო და ესთეტიკური შედეგის დაპირებას (კლინიკა, სალონი) არასდროს იგონებ; გამოქვეყნებამდე ეძებ დარჩენილ დროებით ტექსტს (`lorem`, `TODO`, `example.com`, გამოგონილი ნომერი).
6. **ხარჯი.** დომენი და ფასიანი ტარიფები განმეორებადი ხარჯია, უფასო ტარიფებს კი ლიმიტები აქვს, რომლებიც შეიძლება შეიცვალოს. შენ: არაფერზე არ რეგისტრირდები და არაფერს იხდი — ანგარიში და ბარათი ადამიანისაა; განმეორებად ხარჯს `intent.md`-ის §5-ში და ADR-ში ჩაწერე, ფასი და ლიმიტი კი ოფიციალურ გვერდზე შეამოწმე.
7. **ხელმისაწვდომობა და ქართული ენა.** შენ: `<html lang="ka">` და `<meta charset="utf-8">`, ფაილები UTF-8-ით და LF ხაზის დაბოლოებით (`eol` gate CRLF-ს არ უშვებს); ქართული ასოების მქონე შრიფტი (ზოგ შრიფტს არ აქვს — ეკრანის სურათზე გადაამოწმე); ყველა ფოტოს `alt`; საკმარისი კონტრასტი; ღილაკები ტელეფონზე თითით დასაჭერად საკმარისად დიდი; ფორმის ყოველ ველს წარწერა.
8. **გარე სკრიპტები და გამოქვეყნება.** სტატისტიკა, ჩათი, სოციალური ქსელის ღილაკები და ჩაშენებული რუკები სხვის კოდს ტვირთავს და სტუმარს თვალყურს ადევნებს. შენ: ადამიანის „კი“-ს გარეშე არ ამატებ; რუკას უბრალო ბმულად (Google Maps-ის მისამართი) დებ, გასაღებიანი ჩაშენების ნაცვლად; გამოსაქვეყნებელი რეპო (git-ის საცავი) შეიძლება საჯარო იყოს, ამიტომ პირადი ფოტო, კლიენტების სია და `.env` მასში არ შედის (`secrets` gate ამოწმებს); `git push` — მხოლოდ ადამიანის „კი“-თ.
