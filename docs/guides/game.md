# თამაშის პროექტის სახელმძღვანელო

ეს ფაილი აგენტისთვისაა და ეხება თამაშებს, რომელთა გამოშვებაც დამწყებს რეალურად შეუძლია: ბრაუზერის 2D თამაშებს (არკადა, თავსატეხი, ვიქტორინა, მეხსიერების ბარათები, სიტყვების თამაში) და მარტივ 2D თამაშებს კომპიუტერისთვის. თუ იდეა თამაში არ არის, ან ადამიანს პირველივე ვერსიაში 3D, ონლაინ მულტიპლეერი (რამდენიმე ადამიანი ერთ თამაშში ინტერნეტით), მობილური აპლიკაცია ან გასაყიდი თამაში უნდა და შემცირებაზე არ თანხმდება, გამოიყენე `docs/guides/other.md`. ადამიანი, ჩვეულებრივ, დამწყებია და კოდს ვერ კითხულობს, ამიტომ ყოველი შედეგი ჩვენებით დაამტკიცე და არა დაპირებით, და რაც არ შემოწმებულა, ისიც პირდაპირ თქვი.

## 1. ინტერვიუ — რა ვკითხოთ (ეტაპი 1)

`/intent` ერთ ჯერზე ერთ კითხვას სვამს, 2–3 ვარიანტით და შენი რეკომენდაციით; რაზეც იდეამ უკვე უპასუხა, ის აღარ იკითხება (intent.md-ის §7-ის ზოგადი Q1–Q7 ამ სიაში უკვე შედის). თამაშის იდეაზე კითხვები ამ რიგით დასვი:

1. **რას აკეთებს მოთამაშე ყოველ რამდენიმე წამში?** (ა) რეფლექსი — გაქცევა, დაჭერა, სროლა; (ბ) თავსატეხი — უჯრები, ბარათები, სიტყვები, რიგრიგობით სვლები; (გ) ვიქტორინა — კითხვა და პასუხი ქულებით. რეკომენდაცია: ის, რომელიც იდეას უფრო ჰგავს; თუ ჯერ არ იცის — (ბ) ან (გ), რადგან მათი წესები ეკრანის გარეშეც მოწმდება ტესტებით.
2. **როგორ მთავრდება ერთი რაუნდი?** (ა) სიცოცხლეები ილევა და ქულა რჩება; (ბ) დრო ამოიწურა (მაგ. ერთი წუთი); (გ) მიზანი შესრულდა და დონე გავლილია. რეკომენდაცია: (ა) ან (ბ) — სრულ, გამოსაცდელ თამაშამდე ყველაზე მოკლე გზაა.
3. **ვინ ითამაშებს და სად?** (ა) მე და მეგობრები კომპიუტერზე, ბრაუზერში ბმულით; (ბ) მხოლოდ ჩემს კომპიუტერზე, ჩამოსატვირთი პროგრამით; (გ) ტელეფონზეც. რეკომენდაცია: (ა) — ბმულს ყველა გახსნის და არაფრის დაყენება არ დასჭირდება; (გ) შეხებით მართვას ნიშნავს და ცალკე სამუშაოა. ეს პასუხი სტეკსაც წყვეტს.
4. **რით მართავენ თამაშს?** (ა) კლავიატურით (ისრები ან WASD); (ბ) მაუსით; (გ) შეხებით. რეკომენდაცია: ერთი ხერხი პირველ ვერსიაში — (ა) ან (ბ), რადგან მეორე ხერხი ორმაგ სამუშაოსა და ორმაგ გამოცდას ნიშნავს.
5. **რა იერსახე და ხმა ექნება?** (ა) მარტივი ფორმები და ფერები, ხმის გარეშე; (ბ) ღია ლიცენზიის მზა სურათები და ხმები; (გ) საკუთარი ნახატები და მუსიკა. რეკომენდაცია: პირველ ვერსიაში (ა) — ლიცენზიის რისკი არ არის და თამაში ჯერ წესებით უნდა გამოვცადოთ, სურათებს მერე დავამატებთ.
6. **რომელ ენაზე იქნება ტექსტი?** (ა) ქართულად; (ბ) ინგლისურად; (გ) ორივეზე. რეკომენდაცია: ერთი ენა — მოთამაშეების ენა, რადგან ორი ენა ტექსტისა და გამოცდის მოცულობას ორმაგად ზრდის; ყველა ტექსტი ერთ ფაილში შეინახე, რომ მეორე ენა მერე ადვილად დაემატოს.
7. **უნდა ახსოვდეს თუ არა თამაშს რეკორდი და უნდა უკავშირდებოდეს თუ არა ინტერნეტს?** (ა) არა — განახლებისას ყველაფერი თავიდან იწყება; (ბ) რეკორდი ახსოვდეს ამავე ბრაუზერში, ინტერნეტის გარეშე; (გ) ინტერნეტთან კავშირი — ონლაინ ცხრილი, ანგარიშები ან მულტიპლეერი. რეკომენდაცია: (ა) ან (ბ); (გ)-ს სერვერი, ანგარიშები და თაღლითობისგან დაცვა სჭირდება — ეს ცალკე პროექტია.
8. **როდის და ვის აჩვენებ?** (ა) კლასში ან ჯგუფში, საკუთარი კომპიუტერიდან; (ბ) მეგობრებს ბმულით; (გ) საჯაროდ, თამაშების საიტზე (მაგ. itch.io). რეკომენდაცია: (ა), მერე (ბ), რადგან საჯარო გამოქვეყნება პილოტის (ეტაპი 5) შემდეგ უფრო უსაფრთხოა.

**სად ჩაიწერება (intent.md-ში):** მიზნებად (§2: G1, G2… თითოეული — გაზომვის ხერხით) იქცევა 1-ლი და მე-2 პასუხი და, თუ ადამიანს უნდა, მე-7-ის (ბ) — მაგ. G1: „ერთი სრული რაუნდი თავიდან ბოლომდე თამაშდება“ (გაზომვა: ჩვენებაზე ადამიანი თავად ითამაშებს და წესების ტესტები გადის); „ვისთვის“ (§3) ივსება მე-3 პასუხით; შეზღუდვებად (§5) იწერება პასუხები 3–6 და ვადა (მე-8); „რას არ ვაკეთებთ“-ში (§4) — ყველაფერი, რაზეც ადამიანი „მერე“ ან „არა“ თქვა (მაგ. საკუთარი ხატვა, ონლაინ ცხრილი). რასაც ის თვითონ არ ამბობს და შენი რეკომენდაციით ივსება, **ჰიპოთეზად** მონიშნე, სანამ არ დაადასტურებს. თუ იდეა 3D თამაშია ან ონლაინ მულტიპლეერი, ეს პირველივე კითხვაზე გამოჩნდება: შესთავაზე იგივე თამაში 2D-ში ან ორი მოთამაშით ერთ კომპიუტერზე, დანარჩენი კი „რას არ ვაკეთებთ“-ში ჩაწერე. ჰოსტინგის არჩევანი მერე ADR-ში იწერება.

## 2. რით ავაშენოთ — სტეკის ვარიანტები (ეტაპი 3)

Python-ის ვარიანტისთვის (გ) ჯერ `py -3.12 -m venv .venv` გაუშვი (venv — ვირტუალური გარემო: ამ პროექტის პაკეტების ცალკე საქაღალდე, რომელიც ადამიანის საერთო Python-ს არ ეხება; `.venv` უკვე `.gitignore`-შია და გრაფი მას არ ამოწმებს), მერე კი ყოველი დაყენება და გაშვება `.venv/Scripts/python`-ით შეასრულე. სტეკის (ხელსაწყოების ნაკრების, რომლითაც თამაში შენდება) არჩევანი მე-3 ეტაპზე `/adr`-ით იწერება; ადამიანს ორი-სამი ვარიანტი მარტივად აუხსენი და დამწყებისთვის რეკომენდებული შესთავაზე. თამაში ცალკე საქაღალდეში, `game/`-ში დადე, რომ პროექტის დოკუმენტებს არ აერიოს (Node-ის ვარიანტებში მას თავისი `package.json` აქვს, ამიტომ ძრავის გრაფი მას პროდუქტის კოდად თვლის და მის Markdown-ფაილებს არ ამოწმებს); ბრძანებები პროექტის ძირეული საქაღალდიდან ეშვება და Windows 10/11-ისა და Git Bash-ისთვისაა დაწერილი. ყოველი დაყენება (`winget`, `npm`, `pip`) ადამიანის „კი“-ს ელოდება: უთხარი, რას აყენებ და რატომ. Node-ის დაყენების შემდეგ ტერმინალი (და Claude Code) თავიდან გახსენი, რომ `node` ბრძანება მოიძებნოს. ვერსიებს, ფასებსა და ლიმიტებს აქ განზრახ არ ვწერთ — არჩევისას ხელსაწყოს ოფიციალურ გვერდზე გადაამოწმე, ბრძანებები ისევ მოქმედებს თუ არა. ცხრილებში ხუთი ბრძანებაა: install (დაყენება), run (local — ადგილობრივად გაშვება), lint (კოდის ავტომატური შემოწმება ტიპურ შეცდომებზე), test (ავტომატური ტესტები) და show (როგორ ითამაშებს ადამიანი).

**ა) HTML5 + JavaScript, framework-ის (მზა სამუშაო კარკასის) გარეშე — „რეკომენდაცია დამწყებისთვის“**

- რა არის: ჩვეულებრივი ვებგვერდი (HTML), რომელსაც JavaScript (ბრაუზერის პროგრამირების ენა) აცოცხლებს; მოძრავი ობიექტები canvas-ზეა (ბრაუზერის ხატვის არე), ვიქტორინა და სიტყვების თამაში კი ჩვეულებრივი ღილაკებითა და ტექსტით კეთდება. ფაილები `game/`-შია (`index.html`, `src/`, `tests/`); `game/package.json`-ში ჩაწერე `"type": "module"`, რომ Node-მა ლოგიკის ფაილები ბრაუზერის მსგავსად, მოდულებად წაიკითხოს.
- რატომ დამწყებისთვის: მოთამაშეს ბმული ეყოფა, framework არ არის და ნაკლები რამ გაფუჭდება; ადგილობრივ სერვერს Python უშვებს, რომელიც ძრავას ისედაც სჭირდება, Node კი მხოლოდ lint-ისა და ტესტებისთვისაა საჭირო.
- გამოდგება: თავსატეხისთვის, ვიქტორინისთვის, მეხსიერების ბარათებისთვის და ერთეკრანიანი არკადისთვის. ნაკლი: ბევრი მოძრავი სურათი, ფიზიკა ან გადახვევადი დონე ხელით ბევრ კოდს ითხოვს — მაშინ (ბ) აირჩიე; თუ Node-ის დაყენება საერთოდ არ შეიძლება (მაგ. სასკოლო კომპიუტერი), lint-ისა და ტესტების gate-ები ვერ ჩაირთვება — მაშინ (გ).
- სად მუშაობს და ქვეყნდება: ნებისმიერ ბრაუზერში; ქვეყნდება როგორც სტატიკური ფაილები ჰოსტინგზე (მაგ. GitHub Pages, Netlify, Cloudflare Pages) ან itch.io-ზე (zip, რომლის ძირეულ საქაღალდეში `index.html` დევს — ჩადე `game/`-ის შიგთავსი და არა თავად `game/`).
- ხარჯი: ღია კოდის ხელსაწყოები, ფული მხოლოდ ჰოსტინგზე შეიძლება დაჭირდეს — ფასი და ლიმიტი არჩევისას ოფიციალურ გვერდზე შეამოწმე.

| ნაბიჯი | ბრძანება |
|---|---|
| install | `winget install OpenJS.NodeJS.LTS` (Node; ან ინსტალერი nodejs.org-იდან; ერთხელ), შემდეგ `game/package.json` (აგენტი წერს: `"type": "module"` და სკრიპტები `lint`, `test`) და `npm --prefix game install --save-dev eslint @eslint/js globals` |
| run (local) | `py -3.12 -m http.server 8000 --bind 127.0.0.1 --directory game` |
| lint | `npm --prefix game run lint` (სკრიპტი `"lint": "eslint ."`; კონფიგურაციის ფაილს `game/eslint.config.js` აგენტი წერს ან `game/`-ში გაშვებული `npm init @eslint/config@latest` ქმნის) |
| test | `npm --prefix game test` (სკრიპტი `"test": "node --test"`, ფაილები `game/tests/*.test.js`) |
| show | `start http://127.0.0.1:8000` — თამაში ბრაუზერში იხსნება |

**ბ) Phaser**

- რა არის: JavaScript framework 2D თამაშებისთვის — სცენები, სპრაიტები (პერსონაჟებისა და ობიექტების სურათები), ანიმაცია, შეჯახებები, შეხება და ხმა უკვე შიგნითაა.
- გამოდგება: როცა ბევრი მოძრავი ობიექტია, დონე ეკრანზე გადაადგილდება (scroll) ან თამაში ტელეფონზეც უნდა იმუშაოს. ნაკლი: მეტი ხელსაწყო (Node და Vite — პროექტის ასაწყობი და ადგილობრივად გამშვები ხელსაწყო); ინტერნეტში ბევრი ინსტრუქცია Phaser-ის სხვა ვერსიისაა, ამიტომ დაყენებული ვერსიის ოფიციალური დოკუმენტაციით იხელმძღვანელე, Vitest-ისა და Vite-ის ვერსიების თავსებადობა კი დაყენებისას გადაამოწმე. scaffold (პროექტის საწყისი ფაილების შემქმნელი ბრძანება) კითხვებს სვამს; თუ შენი ტერმინალი პასუხებს ვერ იღებს, ადამიანმა ბრძანება თავის ტერმინალში, პროექტის ძირეულ საქაღალდეში გაუშვას, შენ კი ზუსტად უთხარი, რა აირჩიოს. ლოგიკის ფაილებმა Phaser არ უნდა გამოიყენონ — მხოლოდ ასე შემოწმდება ისინი ტესტებით Node-ში, ეკრანის გარეშე.
- სად მუშაობს და ქვეყნდება: ბრაუზერში; `npm --prefix game run build` ქმნის `game/dist/` საქაღალდეს, რომელიც სტატიკურ ჰოსტინგზე იტვირთება.
- ხარჯი: ღია კოდი; ჰოსტინგის ფასი და ლიმიტი არჩევისას ოფიციალურ გვერდზე შეამოწმე.

| ნაბიჯი | ბრძანება |
|---|---|
| install | `npm create @phaserjs/game@latest game` (scaffold პირდაპირ `game/`-ში; გაუშვი პროექტის ძირეული საქაღალდიდან; კითხვებზე: Web Bundler, Vite, JavaScript), შემდეგ `npm --prefix game install --save-dev vitest eslint @eslint/js globals` |

| lint | `npm --prefix game run lint` (სკრიპტს `"lint": "eslint ."` აგენტი ამატებს `game/package.json`-ში) |

**გ) Pygame**

- რა არის: Python-ის ბიბლიოთეკა 2D თამაშებისთვის; ვიყენებთ `pygame-ce`-ს (pygame-ის საზოგადოების მიერ განვითარებულ ვერსიას — კოდში მაინც `import pygame` იწერება; ორიგინალურ `pygame`-თან ერთად ერთ გარემოში არ დააყენო). კოდი `game/`-შია (შესასვლელი `game/main.py`), ტესტები — `game/tests/`-ში; პროექტის ძირეულ საქაღალდეში აგენტი `pytest.ini`-ს წერს (`testpaths = game/tests`, `pythonpath = game`), ამიტომ `pytest -q` მხოლოდ პროექტის ტესტებს აგროვებს და `game/`-ის მოდულებს ხედავს.
- გამოდგება: როცა თამაში მხოლოდ ადამიანის კომპიუტერზე უნდა თამაშდებოდეს და ადამიანი Python-ის სწავლასაც აპირებს; ძრავის მზა gate-ებიც (`lint` — ruff, `unit` — pytest) იგივე ხელსაწყოებზეა დაწერილი. ნაკლი: ბმულით ვერ გაუგზავნი.
- სად მუშაობს და ქვეყნდება: ადამიანის Windows-კომპიუტერზე; გასაზიარებლად `.exe` უნდა შექმნა (`.venv/Scripts/python -m pip install pyinstaller`, შემდეგ `.venv/Scripts/python -m PyInstaller game/main.py --onefile --windowed`, შედეგი `dist/`-ში; Windows-მა უცნობი `.exe` შეიძლება დაბლოკოს ან მასზე გაფრთხილება გამოიტანოს) ან ვებ-ვერსია pygbag-ით (მხოლოდ `pygame-ce`-ს უჭერს მხარს და შეზღუდვები აქვს — ოფიციალური გვერდი წაიკითხე).
- ხარჯი: ღია კოდის ხელსაწყოები; ვებ-ვერსიის ჰოსტინგის ფასი და ლიმიტი არჩევისას ოფიციალურ გვერდზე შეამოწმე.

| ნაბიჯი | ბრძანება |
|---|---|
| install | `py -3.12 -m venv .venv`, შემდეგ `.venv/Scripts/python -m pip install pygame-ce pytest ruff` |
| run (local) | `.venv/Scripts/python game/main.py` |
| lint | `.venv/Scripts/python -m ruff check game` |
| test | `.venv/Scripts/python -m pytest -q` |
| show | `.venv/Scripts/python game/main.py` — თამაშის ფანჯარა ადამიანის ეკრანზე იხსნება, ბრაუზერი არ სჭირდება |

არჩევანის შემდეგ `/adr`-ით დაწერე სტეკის ADR (არქიტექტურული გადაწყვეტილების ჩანაწერი), სადაც არჩეული სტეკის ეს ხუთი ბრძანება სიტყვასიტყვით წერია, და ადამიანს შეახსენე `/approve adr NNNN`. მე-4 ეტაპის დასაწყისში `tools/gates/gates.toml`-ში ამავე ბრძანებებით ჩაირთვება gate-ები (მანქანური შემოწმებები) `lint` (lint-ის ბრძანებით) და `unit` (test-ის ბრძანებით): `enabled = true`, `cmd` კი არგუმენტების სიაა; gate-ები პროექტის ძირეული საქაღალდიდან და shell-ის გარეშე ეშვება, ამიტომ Node-ის სკრიპტები `npm --prefix game ...`-ით იძახება, მაგ. `["npm", "--prefix", "game", "test"]`, Pygame-ის ხელსაწყოები კი პროექტის ვირტუალური გარემოთი, მაგ. `[".venv/Scripts/python", "-m", "pytest", "-q"]` — მხოლოდ ადამიანის „კი“-ს შემდეგ, რადგან gates.toml დაცული ფაილია. გაითვალისწინე:

- ბრძანებას ADR-ში ჩაწერამდე ერთხელ გაუშვი; რაც არ მუშაობს, არ ჩაიწერება. თუ ხელსაწყო დაყენებული არ არის, gate INCONCLUSIVE-ს (ვერაფერი დამტკიცდა) აბრუნებს და არა წარმატებას, ამიტომ gate ხელსაწყოს დაყენების შემდეგ ჩართე.
- `unit` პირველ ტესტთან ერთად ჩართე: `pytest` ტესტების გარეშე შეცდომით (კოდი 5) სრულდება, `node --test` კი წარმატებით (კოდი 0, `tests 0`) — ასეთი „მწვანე“ არაფერს ამტკიცებს, ამიტომ ბრძანების შედეგში ტესტების რაოდენობა ნახე.
- ჩართვის შემდეგ გაუშვი `py -3.12 tools/gates/gate.py` (უნდა გაიაროს) და ერთხელ განზრახ გააფუჭე ტესტი — gate უნდა გაწითლდეს; მერე გაასწორე.
- `game/`-ის გამზადების (scaffold-ის) შემდეგ გაუშვი `py -3.12 tools/context_graph.py check` — შედეგი `errors=0` უნდა იყოს; Pygame-ის `game/`-ს `package.json` არ აქვს, ამიტომ მის უცხო `.md` ფაილებს (მაგ. რესურსის ნაკრებთან მოყოლილ README-ს) გრაფი ამოწმებს — მათ გაფართოება `.txt`-ით შეუცვალე.

## 3. პირველი ვერსია — რა შედის და რა არა (ეტაპი 2 და 4)

**ყველაზე პატარა სათამაშო ვერსია:** ერთი ეკრანი ან ერთი დონე; ერთი ძირითადი მოქმედება (მოძრაობა, დაჭერა, პასუხის არჩევა, ბარათის გადაბრუნება); მოგებისა და წაგების წესი; საწყისი ეკრანი ღილაკით „თამაში“; თამაშის დასრულების ეკრანი ქულითა და ღილაკით „თავიდან“; მარტივი ფორმები ან ერთი-ორი სურათი, ხმის გარეშე. ერთი რაუნდი რამდენიმე წუთში უნდა დასრულდეს — ასე სწრაფად გამოჩნდება, სახალისოა თუ არა თამაში, სანამ მასზე დიდ დროს დახარჯავთ. გეგმაში (ეტაპი 4) რიგი ასეთია: წესები და მათი ტესტები, მერე ხატვა, მერე მართვა, მერე ეკრანები, ბოლოს ხმა (თუ საერთოდ შედის).

**გადაიდება:** ბევრი დონე, მაღაზია და გაუმჯობესებები, ანიმაციები და ეფექტები, მუსიკა, მეორე ენა, ტელეფონის შეხებით მართვა, რეკორდის შენახვა (თუ მე-7 კითხვაზე (ა) აირჩია), ანგარიშები და ონლაინ ცხრილი. **3D** პირველ ვერსიაში 2D-ად იქცევა: იგივე წესი ზემოდან ან გვერდიდან ხედით, რადგან ნამდვილი 3D ცალკე ხელსაწყოებს, სწავლასა და ბევრად მეტ დროს ითხოვს (მაგ. სათამაშო ძრავა Godot ან Three.js — ისინი ამ სახელმძღვანელოს გარეთაა). **ონლაინ მულტიპლეერი** (სერვერი, ანგარიშები, სინქრონიზაცია, თაღლითობისგან დაცვა) პირველ ვერსიაში ორი მოთამაშით ერთ კლავიატურაზე ან კომპიუტერის წინააღმდეგ თამაშით იცვლება. ყველა გადადებული საკითხი intent.md-ის „რას არ ვაკეთებთ“ ნაწილში იწერება და plan.md-ის backlog-ში (გადადებული ამოცანების სია) ხვდება.

**ტესტებისთვის ერთი წესია აუცილებელი:** თამაშის წესები (ქულა, სიცოცხლე, შეჯახება, მოგება და წაგება, შემთხვევითობა) ცალკე ფაილებშია, რომლებმაც canvas-ის, Phaser-ის ან pygame-ის შესახებ არაფერი იციან (მაგ. `game/src/logic/` ან `game/logic.py`); ხატვა და შეყვანა ცალკეა. მაშინ ტესტები ეკრანის გარეშე გადის და სპეციფიკაციის კრიტერიუმს მანქანა ამოწმებს. კრიტერიუმების მაგალითები, როგორც ისინი სპეციფიკაციაში ჩაიწერებოდა:

- გაშვებისას ჩანს საწყისი ეკრანი ღილაკით „თამაში“, ბრაუზერის კონსოლში (ან pygame-ის ლოგში) შეცდომა არ არის.
- წესების ლოგიკა ცალკე მოდულშია; ყოველ წესზე მინიმუმ ერთი ტესტია, მათ შორის „სიცოცხლე 0-ია → მდგომარეობა: წაგება“.
- ერთი რაუნდი ყოველთვის მთავრდება მოგებით ან წაგებით; დასრულების ეკრანზე ქულა ჩანს, „თავიდან“ კი ქულას 0-ზე აბრუნებს (ტესტი restart ფუნქციაზე).
- შემთხვევითობა ტესტებში ფიქსირებულია (ერთი და იგივე საწყისი რიცხვი), ამიტომ ტესტები ზედიზედ ათჯერ გაშვებისას ერთსა და იმავე შედეგს გვაძლევს.
- თამაში სრულად თამაშდება დაგეგმილი მართვით (მაგ. ისრები და Space), მართვა ეკრანზე წერია და ისრების დაჭერისას გვერდი არ გადაიხვევა.

## 4. როგორ ვაჩვენოთ შედეგი (ეტაპი 5)

მიზანი ისაა, რომ ადამიანმა თამაში თავისი ხელით ითამაშოს და კოდი არ დასჭირდეს. ბრაუზერის თამაშისთვის (ა და ბ):

1. გაუშვი ადგილობრივი სერვერი ფონურად (მე-2 თავის run ბრძანება; თუ პორტი დაკავებულია, სხვა აირჩიე) და შეამოწმე `curl -sI http://127.0.0.1:8000/` (ბ ვარიანტში `http://localhost:8080/`): პირველ ხაზში `200` უნდა ეწეროს. (ა) ვარიანტში იგივე გააკეთე მთავარ `.js` ფაილზეც — `content-type` JavaScript უნდა იყოს. Windows-ის რეესტრში `.js`-ის ტიპი ზოგჯერ `text/plain`-ია; მაშინ ბრაუზერი მოდულს არ ასრულებს და ეკრანი თეთრია — ასეთ დროს სერვერი პატარა `serve.py`-ით გაუშვი, რომელიც `.js`-ს სწორ ტიპს ანიჭებს.
2. გახსენი გვერდი ადამიანისთვის (`start` + მისამართი, Chrome ან Edge); `index.html`-ზე ორმაგი დაწკაპუნება (`file://`) არ გამოდგება — ბრაუზერი მოდულებს და ფაილებს ასე ხშირად არ ტვირთავს.
3. უთხარი, **რა უნდა დაინახოს**: საწყისი ეკრანი და ღილაკი „თამაში“, დაწკაპუნებისას თამაშის ველი და ქულა; **რა სცადოს**: მართვა, რომელიც ეკრანზე წერია (კლავიშები ზუსტად დაასახელე), განზრახ წაგება, ქულის ეკრანი და „თავიდან“, გვერდის განახლება (Ctrl+F5); **როგორ გამოიყურება ჩავარდნა**: თეთრი ან შავი ეკრანი, კლავიშები არ მუშაობს (ჯერ გვერდზე დააწკაპუნოს), თამაში ძალიან სწრაფია ან ნელი, ქართული ასოების ადგილას კვადრატებია, ცვლილება არ ჩანს (ძველი ასლი ბრაუზერის ქეშშია — Ctrl+F5).
4. ეკრანის სურათს ადამიანი Win+Shift+S-ით იღებს, მოკლე ვიდეოჩანაწერს — Win+Alt+R-ით (Xbox Game Bar); თუ Playwright-ის დაყენებას დაეთანხმა (`npx playwright install chromium`), შენ სურათს თავადაც გადაიღებ: `npx playwright screenshot http://127.0.0.1:8000 "$TEMP/game.png"` — სურათი პროექტის გარეთ, დროებით საქაღალდეში რჩება და git-ში არ ხვდება; ადამიანს ფაილის ბილიკი უთხარი.

**Pygame (გ):** `.venv/Scripts/python game/main.py` — თამაშის ფანჯარა ადამიანის ეკრანზე იხსნება; შენ ეკრანს ვერ ხედავ, ამიტომ ადამიანს ჰკითხე, რას ხედავს, და გაშვების ლოგი თავად წაიკითხე. **პილოტი:** 2–3 ადამიანი ითამაშებს ახსნის გარეშე; ჩაიწერე, სად დაიბნენ, და ეს plan.md-ის backlog-ში ან ახალ `/spec`-ში გადაიტანე, ახალ ფუნქციად მაშინვე ნუ აქცევ. ჩვენების ბოლოს პირდაპირ დაასახელე, რა არ შემოწმებულა (მაგ. ტელეფონი, სხვა ბრაუზერი).

## 5. ხაფანგები და უსაფრთხოება

- **ლიცენზიები (სურათი, ხმა, მუსიკა, შრიფტი).** ინტერნეტში ნაპოვნი ყველაფერი გამოსაყენებლად თავისუფალი არ არის, ცნობილი თამაშების პერსონაჟები და მუსიკა კი — საერთოდ არა. აგენტი ჯერ ფორმებს კოდით ხატავს; მზა რესურსს მხოლოდ მკაფიო ლიცენზიით იღებს (მაგ. Kenney-ს ნაკრებები: CC0, ანუ ავტორი ყველა უფლებაზე უარს ამბობს — ოღონდ ნაკრების ლიცენზიის ფაილს მაინც ამოწმებს; შრიფტები: SIL Open Font License) და ყოველი ფაილის წყაროს, ავტორსა და ლიცენზიას `docs/domain/`-ში ჩაწერს; AI-ით გენერირებულ რესურსზე იმ ხელსაწყოს პირობებს ამოწმებს.
- **იდეა ყოველდღე იზრდება.** „კიდევ ერთი დონე“, „მაღაზია“, „ონლაინ“ — თამაშებს ყველაზე ხშირად სწორედ ეს კლავს. აგენტი ამბობს „კარგია, backlog-ში ჩავწერ“, პირველ ვერსიას სპეციფიკაციის კრიტერიუმების მიხედვით ამთავრებს და ახალი ფუნქცია მხოლოდ ახალი `/spec`-ით შემოდის.
- **წარმადობა სუსტ ლეპტოპზე.** აგენტი მოძრაობას დროის მიხედვით ითვლის და არა კადრების მიხედვით (თორემ სწრაფ ეკრანზე თამაში სწრაფია, ნელზე — ნელი), ყოველ კადრზე ახალ ობიექტებს არ ქმნის და ადამიანს სთხოვს, თამაში თავის კომპიუტერზე გაუშვას.
- **კლავიატურა და შეხება.** ტელეფონს ისრები და Space არ აქვს; კომპიუტერზე ისრების დაჭერისას გვერდი გადაიხვევა, სანამ აგენტი ამ ქცევას არ გამორთავს (`preventDefault`). აგენტი მართვას ეკრანზე წერს, ხოლო თუ ტელეფონი შეზღუდვაა, შეხების ღილაკებს ცალკე ამოცანად გეგმავს.
- **შენახვა.** რეკორდი ბრაუზერის ადგილობრივ მეხსიერებაშია (localStorage) — ის თითო მისამართზე ცალკეა (`localhost` და `127.0.0.1` სხვადასხვაა) და ბრაუზერის მონაცემების გასუფთავებისას იშლება. აგენტი წაკითხვა-ჩაწერას try/catch-ში სვამს (თამაში შენახვის გარეშეც უნდა მუშაობდეს) და იქ არაფერ საიდუმლოს ინახავს.
- **ონლაინ სერვისი და საიდუმლოებები.** ბრაუზერში გაგზავნილი კოდი საჯაროა, ამიტომ API გასაღები მასში არ ჩაიდება; თუ სერვისს გასაღები სჭირდება, ის მხოლოდ `.env`-შია და სერვერის მხარეს გამოიყენება (აგენტი `.env`-ს არ კითხულობს). ონლაინ ცხრილში ქულას თამაშის კოდი თავად აგზავნის და ადვილად გაყალბდება, ამიტომ ეს პირველი ვერსიის გარეთაა; თუ ადამიანი მაინც ამას ითხოვს, ეს ცალკე ADR-ში (უსაფრთხოებასთან ერთად) წყდება.
- **ხმა.** ბრაუზერი ხმას პირველ დაწკაპუნებამდე ან კლავიშის დაჭერამდე არ უშვებს; აგენტი ხმას „თამაში“ ღილაკზე დაწკაპუნების შემდეგ რთავს და გამორთვის ღილაკს ამატებს.
- **ქართული ტექსტი ეკრანზე.** ბევრი სათამაშო შრიფტი ქართულ ასოებს არ შეიცავს — ეკრანზე კვადრატები ან ცარიელი ადგილი ჩნდება. აგენტი ქართული ასოების მქონე შრიფტს იყენებს (მაგ. Noto Sans Georgian, ღია ლიცენზიით), ფაილს პროექტში ინახავს და პირველივე ჩვენებაზე ქართულ ტექსტს ეკრანზე ამოწმებს.
