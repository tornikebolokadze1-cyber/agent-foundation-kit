# ADR-0002: მეხსიერების ფენები და სესიის შეჯამების განაწილება

## კონტექსტი

ძრავის პრინციპი ([[intent]] P2, P3): ყოველი სესია უნდა შეჯამდეს, შეინახოს და გადანაწილდეს `progress.md`-სა და `plan.md`-ში; მეხსიერება ფენებად უნდა იყოს დალაგებული, რომ სესიებს შორის ყველაფერი რელევანტური ახსოვდეს; სისტემა თავად უნდა ვითარდებოდეს. ტექნიკური ფაქტები (Claude Code 2.1.27x, გადამოწმებულია): SessionEnd hook-ებს საერთო 1.5 წამიანი ბიუჯეტი აქვთ (მაქს. 60 წმ), მოდელის შეჯამებას კი ~5–50 წამი სჭირდება; compact-ის შემდეგ ეკრანზე რჩება მხოლოდ CLAUDE.md, ავტო-მეხსიერება, SessionStart(compact) hook-ის გამოტანა და რამდენიმე ბოლო ფაილი; 3–4 compact-ის შემდეგ შეჯამების შეჯამება ხარისხს კარგავს.

## გადაწყვეტილება

**ფენები** (სრული რუკა — [[memory/README]]):

| ფენა | სად | ვინ წერს | როდის იტვირთება |
|---|---|---|---|
| სამუშაო | `progress.md` „ახლა" + `plan.md` მიმდინარე ფაზა (auto ბლოკები) | `/session-close` | ყოველ SessionStart-ზე და ყოველი compact-ის შემდეგ, ავტომატურად |
| ეპიზოდური | `memory/episodes/EP-*.md` + INDEX | hook-ები + `/session-close` | მოთხოვნით (INDEX პირველი) |
| სემანტიკური | `intent.md`, specs, ADR, `docs/domain/` | skill-ები + მფლობელის დამტკიცება | გრაფით, მოთხოვნით |
| პროცედურული | `.claude/` skills, agents, rules, hooks; REVIEW.md; gates | მფლობელის თანხმობით | skill-ის გამოძახებისას; rules — ფაილის წაკითხვისას |
| პერსპექტიული | `memory/PROPOSALS.md` + `plan.md` backlog | აგენტი (წინადადება), მფლობელი (გადაწყვეტა) | რაოდენობა — SessionStart-ზე |
| რეფლექსიური | `memory/LESSONS.md` (≤60 ხაზი) | `/reflect`, `/session-close` | ყოველ სესიაში (CLAUDE.md-ის import) |
| დამტკიცებები | `memory/approvals.md` | მხოლოდ `tools/approve.py` | gate-ის LEDGER შემოწმება |
| გრაფი (წარმოებული) | `memory/graph/` (git-ში არა) | `tools/context_graph.py` | SessionStart-ის მოკლე ბრიფი; `query` |

**სესიის ციკლი:**

1. SessionStart (startup / resume / clear / compact) → `episodic.py start`: ხსნის ეპიზოდს და აგენტს აწვდის სამუშაო მეხსიერებას, ბოლო სესიას, წინადადებების რაოდენობას, გადასამოწმებელ სესიებს და compact-ების რიცხვს; ≥3 compact → ურჩევს `/session-close`-ს და ახალ სესიას.
2. PostCompact → რიცხვი იზრდება (`~/.claude/session-state/compacts-<id>`), compact-ის შეჯამება ეპიზოდს ემატება. სტატუსის ზოლში ჩანს `↻N`; ≥3-ზე წითლად: „ახალი სესია → /session-close, მერე /clear".
3. **ძირითადი გზა — `/session-close`:** აგენტი, სრული კონტექსტით, ავსებს ეპიზოდს, აახლებს `progress.md`-სა და `plan.md`-ს, წერს გაკვეთილებს და წინადადებებს, ასწორებს გადასამოწმებელ სესიებს, უშვებს gates-ს და აკეთებს commit-ს.
4. **სათადარიგო ქსელი — SessionEnd:** hook ეპიზოდს წამზე ნაკლებში ხურავს და ნელ ნაწილს **მოწყვეტილ (detached) ფონურ პროცესს** აძლევს: ის Sonnet-ით (ინსტრუმენტების გარეშე, `--restricted`) სტრუქტურირებულ შეჯამებას წერს ეპიზოდში, `progress.md`-ის ჟურნალში — „(ავტო — გადასამოწმებელი)" ჩანაწერს, წინადადებებს — PROPOSALS-ში, და ეპიზოდს ნიშნავს `needs_reconcile`-ით. `plan.md`-ს ავტომატურად **არ** ეხება — მის შესწორებას შემდეგი სესია აკეთებს. თუ სესია `/session-close`-ით დაიხურა და მერე არაფერი მომხდარა, მოდელი საერთოდ არ გამოიძახება.
5. **Catch-up:** ეპიზოდი, რომელიც ≥6 საათია ღიაა (დენი გაითიშა, ფანჯარა მოკვდა), შემდეგ SessionStart-ზე ფონურად იხურება და ჯამდება.
6. **ცარიელი სესია კვალს არ ტოვებს** (ძრავის ავტორის გადაწყვეტილება, 2026-09-22): VS Code ხშირად ხსნის სესიას, რომელშიც არც ერთი შეტყობინება არ იწერება — სამ დღეში ცხრა ასეთმა სესიამ ცარიელი ეპიზოდი და გადასამოწმებელი სიის ხმაური დატოვა. ამიტომ SessionEnd-ზე და catch-up-ზე hook შლის მხოლოდ ისეთ stub-ს, რომლის სესიის ჩანაწერი (transcript) არ არსებობს, მისი საქაღალდე კი არსებობს (საქაღალდის გარეშე — ეს არასწორი გზაა და არა ცარიელი სესია), და ეპიზოდში არც compact, არც შეჯამება, არც `/session-close` არ ყოფილა. ნამდვილი სესია არასდროს იშლება.

**თვითგანვითარება:** `/reflect` ეპიზოდებში ეძებს განმეორებად შეცდომებს და ხელით გამეორებულ ნაბიჯებს და გვთავაზობს skill-ს / rule-ს / gate-ს / ADR-ს PROPOSALS-ში; არაფერი იქმნება მფლობელის „კის" გარეშე.

## განხილული ალტერნატივები

- **შეჯამება პირდაპირ SessionEnd-ში:** 1.5 წამიანი ბიუჯეტი მოკლავდა. უარყოფილია.
- **ავტომატური შეჯამება წერს `plan.md`-საც:** ზედამხედველობის გარეშე მოდელმა გეგმა შეიძლება დააზიანოს. უარყოფილია — მხოლოდ ნიშანი `needs_reconcile`.
- **გარე მეხსიერების სერვისი (vector DB / MCP):** ყოველ შეტყობინებაზე ტოკენები ეხარჯება და მფლობელი ვერ ხედავს. უარყოფილია — ყველაფერი git-ში, Markdown-ად.
- **Haiku შეჯამებისთვის:** იაფია, მაგრამ ქართულ სიტყვებს ამახინჯებს (2.6/5). უარყოფილია.

## შედეგები

- \+ მეხსიერება git-შია, Obsidian-ში ჩანს, და compact-ის შემდეგ თავისით ბრუნდება.
- \+ არცერთი სესია უკვალოდ არ იკარგება, თუნდაც ფანჯარა მოკვდეს.
- − ფონური შეჯამება ყოველ „დაუხურავ" სესიაზე ერთ Sonnet-ის გამოძახებას ხარჯავს (გამოწერის ლიმიტიდან).
- − ავტომატური ჟურნალის ჩანაწერი შეიძლება არაზუსტი იყოს — ამიტომ აქვს ნიშანი და `/session-close` მას ასწორებს.

## დადასტურება

დრილი (`tools/gates/drill.py`): ეპიზოდის შექმნა და ინექცია, compact-ის მრიცხველი, ≥3 რჩევა, SessionEnd → მოწყვეტილი პროცესი → შეჯამება ეპიზოდში + ჟურნალში + წინადადებებში (მოდელის ნაცვლად stub-ით), „სუფთა დახურვაზე" მოდელი არ იძახება, catch-up, სტატუსის ზოლის `↻` ნიშანი, ცარიელი სესიის stub-ის წაშლა (SessionEnd-ზე და catch-up-ზე) და ის, რომ compact-იანი ან არასწორი გზის მქონე ეპიზოდი რჩება.
