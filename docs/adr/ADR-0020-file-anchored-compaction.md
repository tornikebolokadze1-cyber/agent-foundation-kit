# ADR-0020: ფაილებზე მიბმული შეკუმშვა — გრძელი სამუშაო /clear-ის გარეშე გრძელდება

## კონტექსტი

ძრავის ავტორმა ეს ორჯერ ითხოვა. 2026-11-08-ს: „მინდა, რომ ქლეარის და გაგრძელების პროცესის ავტომატიზირებაც მოახდინო,
რათა ხელით არ მომიწიოს ჩარევა". 2026-11-10-ს: „თუ შეიძლება, რომ მომხმარებელი ამ ძრავის არ შევაწუხოთ, და 3 compact-ის
მერე, ავტომატურად ახდენდეს სესიის დახურვას და ახალი სესიის წამოწყებას. ან clear-ს აკეთებს იმავე სესიაში და შემდეგ
გაგრძელებას".

დღევანდელი წესი CLAUDE.md-შია. Claude Code საუბარს თავისით კუმშავს (compact), როცა კონტექსტი ივსება. სტატუს-ხაზი
შეკუმშვებს ითვლის (`↻N`) და სამზე წითლდება, რადგან შეჯამების შეჯამება სანდო მეხსიერება აღარ არის. მაშინ აგენტი
`/session-close`-ს უშვებს და ადამიანს ურჩევს `/clear`-ს და იმავე `/goal`-ის ხელახლა ჩასმას. ორი რამ უკვე ჩანს. პირველი:
ადამიანი ამას ყოველთვის არ აკეთებს — ძრავის აშენების ერთი სესია ↻10-მდე გაგრძელდა. წესი, რომელიც
ადამიანის ხელს ელოდება, რისკს არ აჩერებს, მხოლოდ აფრთხილებს. მეორე: `/goal`-ის შემმოწმებელი ↻3-ის გაჩერებას
შესრულებად არ თვლის და აგენტს ისევ ამუშავებს (იგივე სესია, 2026-11-10). ↻3-ის შემდეგ მუშაობა ისედაც გრძელდება, ოღონდ
შეჯამებით, რომელსაც არავინ ამოწმებს.

Claude Code-ის დოკუმენტაცია (code.claude.com/docs/en/hooks, წაკითხულია 2026-11-08-ს და ხელახლა 2026-11-10-ს) სამ რამეს
ადგენს. პირველი: `/clear`-ს ან ახალ სესიას ვერც hook, ვერც პარამეტრი და ვერც აგენტი ვერ იწყებს — `clear` მხოლოდ
SessionStart-ის წყაროს და SessionEnd-ის მიზეზის სახელია. მეორე: PreCompact hook-ის გამოსავალი შეკუმშვის შეჯამების
ინსტრუქციაა: „When a PreCompact hook exits 0 and doesn't block, Claude Code uses its stdout as instructions for the
compaction summary. Keep that stdout under 10,000 characters per hook." ხელით გაშვებულ `/compact`-ზე hook-ი ადამიანის
ინსტრუქციასაც იღებს (`custom_instructions`), ავტომატურზე ის `null`-ია. მესამე: PostCompact hook-ი მზა შეჯამებას იღებს
(`compact_summary`), მაგრამ მას ვეღარ ცვლის, SessionStart-ს კი `compact` წყაროთი კონტექსტის დამატება შეუძლია — ძრავის
ბრიფი ასე ეწოდება, 9,000 სიმბოლომდე. `/goal` შეკუმშვას უძლებს. ძრავს დღეს PreCompact hook არ აქვს: შეჯამებას
Claude Code-ის ნაგულისხმევი ინსტრუქცია წერს, და ის მთელ საუბარს, წინა შეჯამების ჩათვლით, თავიდან ყვება.

## გადაწყვეტილება

1. **PreCompact hook შეჯამებას ფაილებზე აბამს.** ახალი ბრძანება `episodic.py precompact` stdout-ში ერთ ფიქსირებულ
   ინსტრუქციას ბეჭდავს, 10,000 სიმბოლოზე ბევრად მოკლეს. შეჯამებამ ოთხი რამ უნდა შეინახოს და მეტი არაფერი: (ა) მიმდინარე
   დავალება — მისი ნომერი, ზუსტი ნაბიჯი, შეცვლილი და ჯერ commit-ში არშესული ფაილები, ფონური პროცესები და მათი
   გამოსავლის ფაილები; (ბ) ამ სესიაში ადამიანის ნათქვამი, რომელიც ჯერ არცერთ ფაილში არ ჩაწერილა, სიტყვასიტყვით;
   (გ) ის, რაც სესიამ გაიგო და ჯერ არსად წერია — ხაფანგი, გაზომილი რიცხვი; (დ) სად წერია დანარჩენი — `tasks/todo.md`,
   ეპიზოდი, `progress.md`, commit-ები. რაც git-ში, ფაილებსა და ეპიზოდშია, შეჯამებაში არ მეორდება: შეკუმშვის შემდეგ მას
   ბრიფი და ფაილები აბრუნებს. ხელით `/compact`-ზე ადამიანის საკუთარი ინსტრუქცია ტექსტის თავში რჩება. შეჯამება ოთხ
   ფიქსირებულ სათაურს ატარებს, რომ მისი შემოწმება მანქანამ შეძლოს.
2. **ჩანაწერები შეკუმშვამდე ფაილშია.** აგენტი `tasks/todo.md`-ის „ახლა / შემდეგი"-ს თითო დავალების commit-თან ერთად
   ასწორებს — ამას `/goal`-ის რიგი უკვე ითხოვს. PreCompact hook-ი ინსტრუქციის დაბეჭდვამდე ეპიზოდის გენერირებულ
   „მოქმედებების" ბლოკს წერს (`episodic.py actions`, [[ADR-0018-agentic-graph-layers-and-bridges]] §3), დრო თუ არ ეყოფა —
   ფონურ პროცესში (L-002). ასე შეკუმშვამ შეიძლება მხოლოდ ის დაკარგოს, რაც ჯერ არცერთ ფაილში არ არის, და სწორედ ამას
   ინახავს 1-ლი პუნქტის (ა)–(გ).
3. **PostCompact ამოწმებს, დაემორჩილა თუ არა შეჯამება.** არსებული `episodic.py compact` შეჯამებაში ოთხ სათაურს ეძებს.
   თუ ყველა ადგილზეა, შეკუმშვა „მიბმულია". თუ რომელიმე აკლია, ეპიზოდში ⚠-ხაზი იწერება და სტატუს-ხაზზე ნიშანი ჩნდება:
   შეჯამება ფაილებზე არ არის მიბმული და შეჯამების შეჯამების რისკი ბრუნდება. ეს მანქანური შემოწმებაა და არა მოდელის
   შეფასება — სათაური ან არის, ან არ არის.
4. **↻3 აღარ ნიშნავს „გაჩერდი".** სანამ ყოველი შეკუმშვა მიბმულია, აგენტი აგრძელებს. ↻3-ზე და შემდეგ ყოველ მესამეზე ის
   `/session-close`-ის ჩანაწერების ნაწილს აკეთებს (ეპიზოდი, `progress.md`, `plan.md`, `tasks/todo.md`, commit) და იმავე
   `/goal`-ზე მუშაობს — ადამიანს `/clear` აღარ სჭირდება. ორი მიუბმელი შეკუმშვა ზედიზედ ძველ წესს აბრუნებს:
   `/session-close`, მერე ადამიანს `/clear` და იგივე `/goal` (ძრავის „ორჯერ ჩავარდა" წესი). სტატუს-ხაზი ↻N-ს ისევ
   აჩვენებს, ოღონდ წითლდება მხოლოდ მიუბმელ შეკუმშვაზე. CLAUDE.md-ის აბზაცი, `/session-close` და `/goal`-ის ტექსტი ერთ
   commit-ში იცვლება, რომ ერთი ნაბიჯი ყველგან ერთნაირად ეწეროს (L-018).
5. **რიგი: ძველი წესი არ იცვლება, სანამ ახალი დრილში ARMED არ არის.** აშენება — მხოლოდ `/approve adr 0020`-ის შემდეგ,
   თითო ცვლილება ცალკე commit-ით, დრილითა და მუტაციით: (ა) PreCompact hook-ი და მისი ინსტრუქცია; (ბ) PostCompact-ის
   შემოწმება და სტატუს-ხაზი; (გ) ცოცხალი ზონდი — ნამდვილი შეკუმშვა (ფასიანია, მხოლოდ მფლობელის „კი"-თ, ზუსტი ფასით);
   (დ) ტექსტები — CLAUDE.md, `/session-close`, `/goal`-ის ტექსტი. ნაკრებში — აშენების შემდეგ, ცალკე PR-ით.

## განხილული ალტერნატივები

- **დარჩეს, როგორც არის** — ↻3-ზე `/session-close` და ადამიანის `/clear`. უარყოფილია: ძრავის ავტორმა ორჯერ ითხოვა მისი
  მოხსნა. წესი ადამიანის ხელს ელოდება, და როცა ის არ ჩნდება, სესია მაინც გრძელდება (↻10), ოღონდ ნაგულისხმევი შეჯამებით.
- **„ავტოპილოტი"** — პროგრამა, რომელიც ყოველ დავალებაზე ახალ ფონურ `claude -p "/goal …"` სესიას უშვებს, მკაცრი
  ზღვრით (`--max-turns`, `--max-budget-usd`). ყოველ დავალებას ნამდვილად სუფთა კონტექსტი აქვს. ახლა უარყოფილია: სამუშაო
  ფანჯრის გარეშე მიდის და ფული ადამიანის ყურადღების გარეშე იხარჯება. ფონურ რეჟიმში ნებართვის ფანჯარა ვერ გამოჩნდება,
  ამიტომ მას auto mode ან წინასწარ დაშვებული ხელსაწყოები სჭირდება, რაც ნაკრების სტუდენტისთვის საშიშია. Windows-ზე,
  macOS-სა და Linux-ზე ფონური პროცესის მართვა ცალკე სამუშაოა. თუ მიბმული შეკუმშვა არ გამართლდება (მე-3 პუნქტი ხშირად
  წითლდება), ეს ახალი ADR იქნება.
- **↻3-ზე შეკუმშვის დაბლოკვა** — PreCompact-ს ამის უფლება აქვს. უარყოფილია: დაბლოკილი შეკუმშვის შემდეგ კონტექსტი
  ივსება, გადავსება კი, რომელსაც შეკუმშვა ვეღარ ასუფთავებს, `/goal`-საც შლის. სამუშაო ჩერდება და `/clear` მაინც ადამიანს
  სჭირდება.
- **ზღვრის აწევა** (↻3 → ↻6) შეჯამების შეცვლის გარეშე. უარყოფილია: შეჯამების შეჯამება ისევ გროვდება, უბრალოდ გვიან
  ვამჩნევთ.

## შედეგები

**+** გრძელი `/goal` ადამიანის ჩარევის გარეშე სრულდება. შეკუმშვის შემდეგ აგენტი ბრიფიდან, ფაილებიდან და მოკლე, მიმდინარე
შეჯამებიდან იწყებს, რაც `/clear`-სა და გაგრძელებას თითქმის უდრის. **+** შეჯამება პატარაა: შეკუმშვის შემდეგ ნაკლები
ტოკენია და ქეშის გადაწერა იაფია ([[ADR-0010-prompt-cache-and-cost]]). **+** მიუბმელ შეჯამებას მანქანა ამჩნევს და არა
თვალი.

**−** ახალი hook-ი და harness-ის ფაილების ცვლილება (`episodic.py`, `.claude/settings.json`, სტატუს-ხაზი, CLAUDE.md,
`/session-close`): თითოს დრილი და მუტაცია სჭირდება. **−** ინსტრუქციას როგორ გამოიყენებს, Claude Code წყვეტს, და ეს ახალ
ვერსიაში შეიძლება შეიცვალოს. ამიტომ ცოცხალი ზონდი ძრავის სახელოსნოს ზონდების სიაში ჩაიწერება, და იქაური ბრიფი მის გამეორებას
ახალ ვერსიაზე შესთავაზებს. **−** სხვა PreCompact hook-ი, მაგალითად ადამიანის გლობალური პარამეტრებიდან, საკუთარ
ინსტრუქციას დაამატებს. ჩვენი შემოწმება მაშინაც მხოლოდ ოთხ სათაურს ეძებს და დანარჩენს არ განსჯის. **−** რაც ჯერ არცერთ
ფაილში არ არის და შეჯამებამაც გამოტოვა, მაინც იკარგება. ამიტომ ჩანაწერები თითო დავალების commit-თან ერთად ახლდება (მე-2
პუნქტი), ზუსტ დეტალს კი ჩანაწერიდან `tools/recall.py` აბრუნებს. **−** სუფთა კონტექსტს `/clear` მაინც უკეთ იძლევა.
ადამიანს მისი გაშვება ისევ შეუძლია, უბრალოდ აღარ სჭირდება.

## დადასტურება

- დრილი, `episodic` ჯგუფი: PreCompact-ის stub-payload (`auto`) → stdout-ში ინსტრუქციის ზუსტი ტექსტი (დრილი მას
  სიტყვასიტყვით ამოწმებს, L-018), 10,000 სიმბოლოზე ნაკლები, exit 0, შეკუმშვა არ იბლოკება; `manual` ადამიანის
  ინსტრუქციით → ის ტექსტის თავშია; მუტანტი (ინსტრუქცია ამოღებულია ან ერთი სათაური აკლია) → DEAD.
- დრილი: PostCompact ოთხივე სათაურიანი შეჯამებით → ⚠ არ არის; ერთი სათაურის გარეშე → ⚠ ეპიზოდში და სტატუს-ხაზზე; ორი
  ზედიზედ → ბრიფი ძველ წესს ასახელებს (`/clear`); მუტანტები → DEAD.
- ცოცხალი ზონდი (L-009; ფასიანია — მხოლოდ მფლობელის „კი"-თ, ზუსტი ფასით): ნამდვილ `claude` სესიაში ხელით `/compact` და
