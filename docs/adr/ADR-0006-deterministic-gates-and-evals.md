# ADR-0006: დეტერმინისტული კარიბჭეები და evals

## კონტექსტი

ძრავის პრინციპი ([[intent]] P7): კოდირების ძრავაში სერიოზული ტესტირება, კარიბჭეები და შეფასება, რომელიც მანქანურად შეამოწმებს დაწერილს და დაიჭერს იმას, რასაც მოდელები (ორკესტრაციაც) გამოტოვებენ; დავიწყოთ თანდათან. ორი ცნობილი ხაფანგი: (1) შემოწმება, რომელიც ვერასდროს ჩავარდება, და შემოწმება, რომელიც არ გაეშვა, ერთნაირ „მწვანე" ხაზს ბეჭდავს; (2) გამოტოვებული შემოწმება ადვილად ითვლება „გავლილად".

## გადაწყვეტილება

1. **ერთი runner, ერთი სია:** `tools/gates/gate.py` + `tools/gates/gates.toml` ([[tools/gates/README]]). exit: `0` ყველა ჩართული gate გავიდა · `1` რაღაც ჩავარდა · `2` INCONCLUSIVE (ვერ გაეშვა ან ნული ფაილი შეამოწმა). გამორთული gate ბეჭდავს SKIP-ს და **SKIP არ არის PASS** — შემაჯამებელ ხაზში ყოველთვის ჩანს, რამდენმა არაფერი დაამტკიცა. ყოველი ხაზი ასახელებს, რა შეამოწმა სინამდვილეში (`[input: git ls-files]`).
2. **დონეები, თანდათან:**
   - **0 — ახლა:** `graph` (ბმულები, frontmatter, სტატუსები, ჯაჭვი, ჟურნალი), `json`, `toml`, `python` (სინტაქსი), `shell` (`bash -n`), `eol` (CRLF), `secrets` (gitleaks), `drill`.
   - **1 — სტეკის ADR-თან ერთად:** `ruff`, `pytest`.
   - **2 — როცა აგენტი პასუხობს:** evals — ქართული (deterministic ≥95%, adversarial ≥95%, გრამატიკა ≥4.3/5; ნაკრები პირველი სპეციფიკაციიდან იწერება) და grounding-ის ინვარიანტები (დომენის ურღვევი წესები — [[REVIEW]]) — [[evals/README]].
   - **3 — საჯარო პილოტამდე:** დამოკიდებულებების აუდიტი, SAST, e2e.
3. **სად ეშვება:** `.githooks/pre-commit` (`core.hooksPath=.githooks`, მხოლოდ ამ რეპოს ლოკალური კონფიგი) ყოველ commit-ზე; Stop hook — სესიის მიერ შეცვლილ ფაილებზე ყოველი ტურის ბოლოს; ხელით — `py -3.12 tools/gates/gate.py`. მოგვიანებით — CI (P-003).
4. **დრილი:** `tools/gates/drill.py` ყოველ gate-ს, guard-ის წესს და hook-ს ჯერ სუფთა კონტროლზე უშვებს (უნდა გაიაროს), მერე განზრახ ჩადებულ დეფექტზე (უნდა ჩავარდეს **საკუთარი** მარკერით, არა ნებისმიერი ტექსტით). `--self-test` თავად დრილს ამოწმებს: ყველა შემოწმებას „ყოველთვის წარმატებული" stub-ით ცვლის — დრილმა მაშინ DEAD უნდა თქვას, თორემ ის რეზინის ბეჭედია.
5. **წესები:** ზღვარი არასდროს დაიწევს და gate არ გამოირთვება „გასამწვანებლად"; `--no-verify` აკრძალულია (deny + guard B2); ყოველ ახალ gate-ს დრილი მოჰყვება; gates-ის ფაილები დაცულია (ask).
6. **კოდის review მოდელებით** (Sol, critic-ები) — დამატებითი ფენაა, არა ჩანაცვლება: CRITICAL/HIGH ბლოკავს, ორზე მეტი შესწორების ბრუნი არ არის — შემდეგ „UNVERIFIED" და მფლობელი.

## განხილული ალტერნატივები

- **pre-commit framework (Python პაკეტი):** კარგი ეკოსისტემა, მაგრამ ახალი დამოკიდებულებაა და Windows-ზე ცალკე დაყენებას ითხოვს. ჯერ არა; `gate.py` stdlib-ზეა.
- **ყველაფერი ერთდროულად (lint, tests, evals, SAST) დღიდანვე:** კოდი ჯერ არ არსებობს — ცარიელი შემოწმებები „მწვანედ" გამოჩნდებოდა. უარყოფილია; დონეები ირთვება, როცა შესამოწმებელი გაჩნდება.

## შედეგები

- \+ ის, რაც მანქანურად იჭერება, მოდელის კეთილსინდისიერებაზე აღარ არის დამოკიდებული.
- \+ ყოველი gate დამტკიცებულად „ცოცხალია" — დრილი ამას ყოველ commit-ზე ამოწმებს.
- − commit რამდენიმე წამით ნელდება (დრილი).
- − მოდელის ფარული ლოგიკური შეცდომა ადეკვატურად გამოყურებულ ტესტს მიღმა მაინც შეიძლება გაიპაროს — ეს დასახელებული სუსტი წერტილია და არა მოგვარებული.

## დადასტურება

`py -3.12 tools/gates/drill.py` — ყველა ARMED (exit 0); `py -3.12 tools/gates/drill.py --self-test` — stub-ებით DEAD (დრილი ცოცხალია).
