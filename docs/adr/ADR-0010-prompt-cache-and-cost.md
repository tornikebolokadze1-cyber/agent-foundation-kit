# ADR-0010: ქეშირება და ხარჯი

## კონტექსტი

**ძრავის ავტორი (2026-10-10):** „ჩემი მიზანია, Anthropic-ის ქეშირების შესაძლებლობების მაქსიმუმი გამოვიყენო და ჩავდო ამ ძრავაში, რათა მოვახდინო ხარჯების მაქსიმალური დაზოგვა"; ვარიანტების ანალიზის შემდეგ, იმავე დღეს: „ჩაინიშნე ეს ყველაფერი სადმე … კეთებაც დაიწყე ყველაფრის, რაც მირჩიე, უშუალოდ. და ასევე, სტატუსლაინის თემაც მინდა ჩავნიშნოთ პროექტში, რათა ძრავში დეფოლტად იდოს უკვე სტატუსლაინის გაკეთებაც" (ციტატებში მხოლოდ მართლწერაა გასწორებული).

გაზომვა ძრავის აშენების სესიებზე ჩატარდა (2026-10-10); აქ მხოლოდ ის, რაც გადაწყვეტილებას განსაზღვრავს. იმ სესიებში შემავალი ტექსტის 98.1% უკვე ქეშიდან (ტექსტის შენახული ასლიდან) იკითხება — ქეშირება Claude Code-ში ჩართულია და თითქმის მაქსიმუმზე მუშაობს. ხარჯი (API-ის ფასით ≈ $211, გამოწერის ლიმიტის საზომად) სამი რამისგან მოდის: დიდი კონტექსტის ყოველ ნაბიჯზე კითხვა (60%), ასლის ჩაწერა (26%) და პასუხი (14%). ყველაზე დიდი ერთი წყარო რეპოზიტორიების კვლევის subagent-ებია Sonnet 5.5-ზე (44%, მედიანური კონტექსტი 311 ათასი ტოკენი). მთავარ სესიებში ჩაწერის ~45% (≈ $17) აცილებად „თავიდან აწყობაზე" მოვიდა: საათზე გრძელი პაუზა, Claude Code-ის გადატვირთვა, compact, მოდელის შეცვლა. მთავარი სესიის ასლი ერთ საათს ცოცხლობს, subagent-ისა — ხუთ წუთს (გაზომილია). იმავე დღის სამუშაომ კიდევ ერთი მიზეზი აჩვენა: ნებართვის მოთხოვნამ (ფაილზე, რომლის შეცვლაც მფლობელის თანხმობას ითხოვს) 12.6 საათი დაიცადა და პასუხის შემდეგ 310 ათასი ტოკენი თავიდან ჩაიწერა (≈ $2.5). ამიტომ ბერკეტი „ქეშირების ჩართვა" კი არ არის, არამედ ნაკლები და პატარა კონტექსტი, იშვიათი თავიდან აწყობა, იაფი მოდელი კითხვით დატვირთულ საქმეზე — და ეს ყველაფერი თვალით უნდა ჩანდეს.

## გადაწყვეტილება

**1. გაზომვა ძრავის ნაწილია.** `tools/cache_cost.py` ყოველ მოდელის გამოძახებას აფასებს `tools/model_prices.toml`-ის ფასებით და ყოველ „თავიდან აწყობას" მიზეზს არქმევს; `/observatory` (`tools/observe.py`) ანგარიშს ემატება ნაწილი „ქეში და ხარჯი", ხოლო `--brief` ხაზი — ღირებულება და ქეშის წილი, რომელიც `/session-close`-ით ეპიზოდში რჩება. „თავიდან აწყობად" ითვლება ნაბიჯი, რომელმაც უკვე არსებული კონტექსტის 50 ათასზე მეტი ტოკენი ხელახლა ჩაწერა — ახალი შინაარსი არ ითვლება. ფასის არმქონე მოდელი „ფასის გარეშე" ჩანს და ჯამში არ შედის (ნულად არასდროს ითვლება); წაუკითხავი ფასების ფაილი — „ფასი უცნობია" და არა $0. ფასი იცვლება მხოლოდ `model_prices.toml`-ში, წყაროს ხაზით.

**2. statusline ნაგულისხმევად.** `.claude/hooks/statusline.py` მიბმულია პროექტის `.claude/settings.json`-ში (`statusLine`, განახლება ყოველ 15 წამში). ჯერ მფლობელის საკუთარ statusline-ს უშვებს (`~/.claude/settings.json`-ის `statusLine.command`), რომ პროექტის პარამეტრმა ის არ დამალოს; თუ ასეთი არ არის ან ჩავარდა, თავად ბეჭდავს მოკლე ხაზს (მოდელი, კონტექსტის %, compact-ების მთვლელი ↻N). შემდეგ ამატებს ქეშის ხაზს. მდგომარეობას Claude Code-ის საკუთარი `prompt_cache` ველიდან იღებს (2.1.295-ში ეს ველი უკვე აქვს: თბილია თუ არა, როდის იწურება, რამდენი ჩაიწერება თავიდან), ხოლო თუ ველი არ არის — სესიის ჩანაწერის ბოლოდან: ასლი თბილია ~HH:MM-მდე; იწურება N წუთში (10-ზე ნაკლები); ცივია და კონტექსტი დიდია (150 ათასი ტოკენიდან) — რამდენი ტოკენი ჩაიწერება თავიდან, დაახლოებით რა ფასად, და რომ ახალი თემისთვის ახალი სესია იაფია; ცივია, მაგრამ კონტექსტი პატარაა. ვადას (1 საათი თუ 5 წუთი) ბოლო ჩაწერიდან კითხულობს და არა მუდმივიდან. შეცდომაზე არასდროს ჩავარდება; თუ ჩანაწერს ვერ კითხულობს, წერს „უცნობია" — „თბილს" არასდროს. ნაკრებიდან ყოველი ახალი პროექტი ამას თავიდანვე იღებს.

**3. ჩვევები** ([[process]] §5): მოდელი პირველ შეტყობინებამდე ირჩევა და შუაში არ იცვლება; ერთი თემა — ერთი სესია; ასლის ვადაზე (საათზე) გრძელი პაუზის შემდეგ, თუ საუბარი დიდია, — `/session-close` და ახალი სესია; დიდ სესიაში VS Code-ისა და Claude Code-ის თავიდან გახსნას ვერიდებით (გადატვირთვა = თავიდან აწყობა); ნებართვის მოთხოვნას, თუ შესაძლებელია, მაშინვე ვპასუხობთ — საათზე გრძელი მოლოდინიც თავიდან აწყობაა (შეტყობინება ასეთ დროს — P-006); ↻2–3-ის შემდეგ — ახალი სესია.

**4. subagent-ები** (CLAUDE.md): ვიწრო კითხვა, შეზღუდული კითხვა, მოკლე პასუხი — სამიზნე კონტექსტი 100 ათას ტოკენამდე. მოდელი: შემოწმება (კრიტიკოსები, verifier) — Opus 5.5 ([[ADR-0005-maker-checker-orchestration]]-ის როლებით); მსჯელობა და ყველაფერი ქართული — Sonnet 5.5; მექანიკური ძებნა და ჩამონათვალი ინგლისურად — Haiku 5.5; კითხვა-შეჯამება Haiku-ზე გადადის მხოლოდ მისი ხარისხის გაზომვის შემდეგ (P-005). ქართულ ტექსტს Haiku არ წერს (L-006).

**5. მუდმივად ჩატვირთული ტექსტი.** პროექტისა (~20 KB) ბიუჯეტში რჩება. მფლობელის გლობალური ინსტრუქციები (`~/.claude/CLAUDE.md` და წესები) ყველა პროექტის ყოველ სესიაში იტვირთება და ყოველ ნაბიჯზე ტოკენს ხარჯავს — ისინი მისი ფაილებია და შემცირებას თავად წყვეტს; ჯერ `/context`-ით უნდა გაიზომოს, რამდენს იკავებს.

**6. პროდუქტი (F3) — პრინციპები სტეკის ADR-ისთვის.** როცა პროდუქტი API-ს თავად გამოიძახებს: უცვლელი ნაწილი თავში (ხელსაწყოები → სისტემური ინსტრუქცია → ცოდნის ბაზა და დომენის დოკუმენტები), საუბარი — ბოლოს; ერთი აშკარა breakpoint (ქეშის საზღვარი) უცვლელი ნაწილის ბოლოს და ავტომატური ქეშირება საუბრის კუდისთვის; TTL მოთხოვნებს შორის შუალედით (უწყვეტ ნაკადზე — 5 წუთი, 5–60-წუთიან შუალედზე — 1 საათი); არასასწრაფო სამუშაო Batch API-ით (ნახევარ ფასად); ტესტებში cache diagnostics (beta) და შემოწმება, რომ მეორე იდენტური მოთხოვნა ქეშიდან კითხულობს. შეზღუდვები, რომლებიც დიზაინმა უნდა გაითვალისწინოს: ქეშირდება 512 ტოკენიდან (5.5 მოდელებზე), მაქსიმუმ 4 breakpoint, 20 ბლოკის lookback. აქ მხოლოდ ჩაწერილია; განხორციელდება სტეკის ADR-ით.

**რას არ ვაკეთებთ:** „გამაცოცხლებელ" შეტყობინებებს Claude Code-ში (იაფი გზა მხოლოდ API-შია: `max_tokens: 0`); ძრავის API გასაღებზე გადაყვანას; compact-ის ზღვრის ბრმად დაწევას.

## განხილული ალტერნატივები

- **არაფრის კეთება — ქეში ისედაც 98%-ზეა.** უარი: აცილებადი თავიდან აწყობა (≈ $17) და subagent-ების წილი (44%) გაზომილი, რეალური ბერკეტებია; გაზომვის გარეშე კი ვერცერთ დანაზოგს ვერ დავამტკიცებთ.
- **ძრავი API გასაღებზე, საკუთარი ქეშირებით** (აშკარა breakpoint-ები, წინასწარ გათბობა, keep-alive). უარი: გამოწერის ნაცვლად ყოველ ტოკენში გადავიხდით, ხოლო Claude Code ქეშირებას უკვე აკეთებს — დამატებით დასაჭერი კოდი გაჩნდებოდა. ხელახლა განიხილება, თუ გამოწერა აღარ გვეყოფა.
- **hook, რომელიც გრძელი პაუზის შემდეგ ახალ სესიას აიძულებს** (მოთხოვნას ბლოკავს). უარი: მფლობელს შეიძლება შეგნებულად სურდეს იმავე თემის გაგრძელება; ბლოკი არჩევანს წაართმევდა. statusline აფრთხილებს და გადაწყვეტილებას მფლობელს უტოვებს.
- **პროექტის ცალკე statusline, მფლობელის გლობალურის ნაცვლად.** უარი: მფლობელი დაკარგავდა თავის statusline-ს (ლიმიტები, ხარჯი, git); შემფუთავი მას ინარჩუნებს.
- **statusline Node-ზე, გლობალურის მსგავსად.** უარი: ძრავის ერთადერთი აუცილებელი დამოკიდებულება Python 3.12-ია (ყველა hook), Node კი სხვა კომპიუტერზე შეიძლება არ იყოს.

## შედეგები

**+** ყოველი სესიის ღირებულება და თავიდან აწყობის მიზეზები ჩანს (`/observatory`, ეპიზოდის მოკლე ხაზი). **+** მფლობელი მუშაობისას ხედავს, როდის იწურება ასლი, და ჩვევებს მანქანური შეხსენება აქვს. **+** ყველაზე დიდ გაზომილ ხარჯს (subagent-ები) წესი აქვს. **+** ნაკრები ყველაფერს ახალ პროექტებში გადაიტანს.

**−** ფასები ხელით ინახება: მოძველებული ფაილი არასწორ დოლარს აჩვენებს (შემსუბუქება: წყარო ანგარიშში იბეჭდება; უცნობი მოდელი „ფასის გარეშეა"). **−** მიზეზები ჩანაწერების ნიშნებიდან იცნობა, Claude Code-ის ჩანაწერების ფორმატი კი საჯარო კონტრაქტი არ არის; რასაც ვერ ვცნობთ, „უცნობში" ჩანს. **−** statusline ყოველ 15 წამში Python-ს (და მფლობელის statusline-ს) უშვებს. **−** Haiku-ს ხარისხი კითხვაზე ჯერ გაზომილი არ არის (P-005) — მანამდე Haiku მხოლოდ მექანიკურ ძებნას აკეთებს.
