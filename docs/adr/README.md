# არქიტექტურული გადაწყვეტილებები (ADR)

ADR (Architecture Decision Record — არქიტექტურული გადაწყვეტილების ჩანაწერი) ინახავს ყოველ ძირეულ გადაწყვეტილებას: რა პრობლემა იყო, რა ვარიანტები განვიხილეთ, რა ავირჩიეთ და რა ფასად. ახალს წერს `/adr` skill, სტატუსით `proposed`. გადაწყვეტს მხოლოდ მფლობელი: `/approve adr N` (accepted) ან `/approve reject adr N მიზეზი` (rejected). მიღებული ADR აღარ იცვლება — თუ გადაწყვეტილება იცვლება, იწერება ახალი ADR ველით `supersedes`, და მისი დამტკიცებისას ძველი ავტომატურად ხდება `superseded`.

ეს ათი ADR ძრავის გადაწყვეტილებებია: ძრავის ავტორმა ისინი 2026 წლის სექტემბერ–ოქტომბერში დაწერა და ყოველ ახალ პროექტს ნაკრებთან ერთად მოჰყვება. ყველა მათგანს frontmatter-ში აქვს `scope: engine` — ეს ძრავის საკუთარი სამუშაო წესებია, ამიტომ ეტაპების გამტარი მათ არ ითვლის და შენგან დამტკიცებას არ ელოდება ([[ADR-0011-idea-first-stage-conductor]]); თუ მაინც გინდა რომელიმეს მიღება ან უარყოფა, `/approve adr N` მუშაობს. ტექსტებში დარჩენილი ციტატები ავტორის მოთხოვნებია, რიცხვები კი — მისი გაზომვები ძრავის აშენებისას. ნომერი 0008 დაკავებულია ძრავის მომავალი გადაწყვეტილებისთვის (პროცესის შერჩევა დავალების ზომისა და რისკის მიხედვით) და ნაკრებში ჯერ არ შედის. პროექტის საკუთარი გადაწყვეტილებები (სტეკი, მონაცემები, ჰოსტინგი) ADR-0012-დან იწყება, `scope`-ის გარეშე — სწორედ მათი დამტკიცება გადაიყვანს პროექტს მე-3 ეტაპიდან (არქიტექტურა) მე-4-ზე.

სტატუსის ცხრილი ხელით ახლდება `/adr`-ით; ზუსტი მდგომარეობა ყოველთვის — `py -3.12 tools/context_graph.py pending` და ფაილის frontmatter.
