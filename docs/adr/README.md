# არქიტექტურული გადაწყვეტილებები (ADR)

ADR (Architecture Decision Record — არქიტექტურული გადაწყვეტილების ჩანაწერი) ინახავს ყოველ ძირეულ გადაწყვეტილებას: რა პრობლემა იყო, რა ვარიანტები განვიხილეთ, რა ავირჩიეთ და რა ფასად. ახალს წერს `/adr` skill, სტატუსით `proposed`. გადაწყვეტს მხოლოდ მფლობელი: `/approve adr N` (accepted) ან `/approve reject adr N მიზეზი` (rejected). მიღებული ADR აღარ იცვლება — თუ გადაწყვეტილება იცვლება, იწერება ახალი ADR ველით `supersedes`, და მისი დამტკიცებისას ძველი ავტომატურად ხდება `superseded`.

ეს ჩვიდმეტი ADR ძრავის გადაწყვეტილებებია: ძრავის ავტორმა ისინი 2026 წლის სექტემბერ–ნოემბერში დაწერა და ყოველ ახალ პროექტს ნაკრებთან ერთად მოჰყვება. ყველა მათგანს frontmatter-ში აქვს `scope: engine` — ეს ძრავის საკუთარი სამუშაო წესებია, ამიტომ ეტაპების გამტარი მათ არ ითვლის და შენგან დამტკიცებას არ ელოდება ([[ADR-0011-idea-first-stage-conductor]]); თუ მაინც გინდა რომელიმეს მიღება ან უარყოფა, `/approve adr N` მუშაობს. ტექსტებში დარჩენილი ციტატები ავტორის მოთხოვნებია, რიცხვები კი — მისი გაზომვები ძრავის აშენებისას. ნომერი 0016 ძრავის სხვა გადაწყვეტილებისთვისაა დაკავებული და ნაკრებში არ შედის. 0001–0099 ძრავს ეკუთვნის — მისი მომავალი ADR-ები ამ შუალედში დაიწერება, რომ ნაკრების განახლებისას შენი პროექტის ADR-ს ნომრით არ დაემთხვეს. პროექტის საკუთარი გადაწყვეტილებები (სტეკი, მონაცემები, ჰოსტინგი) ამიტომ ADR-0100-დან იწყება, `scope`-ის გარეშე — სწორედ მათი დამტკიცება გადაიყვანს პროექტს მე-3 ეტაპიდან (არქიტექტურა) მე-4-ზე.

სტატუსის ცხრილი ხელით ახლდება `/adr`-ით; ზუსტი მდგომარეობა ყოველთვის — `bash .claude/hooks/py.sh tools/context_graph.py pending` და ფაილის frontmatter.
