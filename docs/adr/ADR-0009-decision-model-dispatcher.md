# ADR-0009: Decision model — დისპეჩერი

## კონტექსტი

**ძრავის ავტორი (2026-10-09):** „მინდა, ამ საწყის ძრავაში ჩავაინტეგრიროთ Decision model-ის შესაძლო გამოყენება, Jev-ის მაგალითად, რომ გარკვეულ თასქებზე ის იქნება პასუხისმგებელი" (ციტატაში მხოლოდ მართლწერაა გასწორებული). სამი ვარიანტიდან (დისპეჩერი / მხოლოდ ცარიელი სლოტი / სფეროს დავალებების ტრიაჟი) ავტორმა აირჩია **დისპეჩერი**: ყოველ დავალებაზე შეთავაზება, რომელ მოდელს გადაეცეს.

Decision model ენის მოდელისგან იმით განსხვავდება, რომ ტექსტს არ წერს. იღებს მდგომარეობას (state — მაგ. დავალების მოკლე აღწერას) და ტიპიზებულ კითხვებს — `choice` (ერთი რამდენიმედან), `noul` (კი / არა), `score` (ქულა) — და აბრუნებს ალბათობებს. TypeSafe-ის Jev („System 1" მოდელი) OpenRouter-ის Decisions API-თ არის ხელმისაწვდომი (`POST https://openrouter.ai/api/alpha/decisions`, მოდელი `~typesafe/jev-latest`), TypeSafe-ის მოსაწვევის გარეშე.

**რა ვიცით გაზომვით** — ძრავის ავტორის სხვა პროექტიდან (2026-09-27): პასუხის მედიანური დრო 325–343 ms; $0.042 1M შემავალ ტოკენზე, გამომავალი უფასოა; 1 196 გადაწყვეტილება $0.0435 დაჯდა (იგივე Opus 4.8-ზე — მინიმუმ $6.98, ~160-ჯერ მეტი); 0.85-ზე მაღალი დარწმუნებულობისას პასუხი არსებულ ეტიკეტს 79%-ში ემთხვეოდა, დაბალზე — 52%-ში; ქართულ ტექსტზე დარწმუნებულობა დაბალი იყო (კავშირების ტიპიზაციის 78% ადამიანთან წავიდა). ეს სხვა პროექტისა და სხვა დავალების გაზომვაა — აქ მხოლოდ საწყისი წერტილია და ჩართვამდე თავიდან გაიზომება.

რისკები: API „alpha"-ა — შეიძლება შეიცვალოს ან გაქრეს. Jev მანქანის გარეთ მუშაობს (OpenRouter და TypeSafe); თუ პროდუქტი კონფიდენციალურ დოკუმენტებთან ან პერსონალურ მონაცემებთან იმუშავებს, რა რომელ სერვისს შეიძლება გადაეცეს, ღია კითხვაა ([[intent]] Q4).

## გადაწყვეტილება

1. **ფენა და არა კონკრეტული მოდელი.** `orchestration/decide.py` — ერთი ინტერფეისი: მდგომარეობა + ტიპიზებული კითხვები → ალბათობები. პირველი პროვაიდერი — Jev OpenRouter-ით (`config.toml`: `[decision] provider = "openrouter:~typesafe/jev-latest"`); სხვა decision model ახალი პროვაიდერით ჩაჯდება. კლიენტი ჯერ დასაწერია (ავტორს სხვა პროექტში გამოცდილი კლიენტი უკვე აქვს).
2. **პირველი დავალება — დისპეჩერი.** `py -3.12 orchestration/decide.py route --task "<დავალების მოკლე აღწერა>"` სვამს ერთ `choice` კითხვას: რომელ ზოლს ერგება დავალება — `routine` (Haiku 5.5), `code` (Sonnet 5.5) თუ `architecture` (Opus 5.5); კრიტერიუმები [[ADR-0005-maker-checker-orchestration]]-დანაა. პასუხი: ზოლი, მოდელი, დარწმუნებულობა.
3. **ზღვარი და „ეჭვისას — უფრო ძლიერი".** დარწმუნებულობა ზღვარზე მაღალია (საწყისი 0.85 — ავტორის გაზომვით, კალიბრაციით დაზუსტდება) → შეთავაზებული ზოლი. ზღვარს ქვემოთ → შეთავაზებულსა და `code`-ს შორის უფრო ძლიერი: დაუჯერებელი „routine" Sonnet-ზე ადის, „architecture" Opus-ზე რჩება — ეჭვისას იაფზე არასდროს ჩამოდის. თუ Jev გამორთულია, არ პასუხობს, შეცდომას აბრუნებს ან ბიუჯეტი ამოიწურა → ნაგულისხმევი ზოლი `code` (Sonnet 5.5). მუშაობა დისპეჩერის გამო არასდროს ჩერდება.
4. **მხოლოდ სთავაზობს.** პასუხი შეთავაზებაა — იბეჭდება და ჟურნალში იწერება; მოდელს ირჩევს სესია ან მფლობელი. შეთავაზებაზე მოქმედება მთავარი სესიის მოდელს არ ცვლის: სამუშაო შეთავაზებული მოდელის subagent-ს ან `claude -p`-ს გადაეცემა, რომ მთავარი სესიის prompt cache არ დაიკარგოს ([[ADR-0005-maker-checker-orchestration]], გადაწყვეტილება 2). დისპეჩერი ვერასდროს გადაწყვეტს იმას, რაც ფულს მოძრაობს, კომპანიას ავალდებულებს ან ჭეშმარიტ ჩანაწერს ცვლის — ეს დეტერმინისტული კოდისა და მფლობელის საქმეა ([[REVIEW]]-ის დომენის ინვარიანტი). კარიბჭეები მასზეც მაღლა დგას.
5. **მონაცემების საზღვარი.** Jev იღებს მხოლოდ აგენტის დაწერილ მოკლე აღწერას (მაქსიმუმ 1 000 სიმბოლო) — არასდროს დოკუმენტის ტექსტს, ხელშეკრულებას, საუბრის ჩანაწერს ან პერსონალურ მონაცემს. გაგზავნამდე დეტერმინისტული შემოწმება: გასაღებები იმალება (`tools/redact.py`, [[ADR-0007-ai-security-and-observability]]); თუ ტექსტი პერსონალურ მონაცემს ჰგავს (ელფოსტა, ტელეფონი, 11-ნიშნა პირადი ნომერი), გაგზავნა იბლოკება (exit 5). ეს შემოწმება განგაშია და არა სრული დაცვა. საზღვრის შეცვლა მფლობელის გადაწყვეტილებაა, Q4-თან ერთად.
6. **ხარჯის ორი საკეტი.** დღიური ბიუჯეტი (საწყისი $0.30, ავტორის პრაქტიკით) ჟურნალიდან ითვლება; ამოწურვისას → exit 4 და ნაგულისხმევი ზოლი. მეორე საკეტი OpenRouter-ის მხარესაა: ამ პროექტისთვის ცალკე გასაღები ხარჯის ლიმიტით (ქმნის მფლობელი; სხვა პროექტის გასაღებს არ ვიზიარებთ).
7. **ჟურნალი.** ყოველი გამოძახება → ერთი JSONL ხაზი `orchestration/decisions/<წელი-თვე>.jsonl`-ში: დრო, აღწერა, ალბათობები, დარწმუნებულობა, ზღვარი, საბოლოო ზოლი, ფასი, მოდელის ვერსია, პასუხის დრო. git-ში ინახება — მფლობელი ხედავს, რა გადაწყვიტა დისპეჩერმა და რა დაჯდა.
8. **გასაღები.** `OPENROUTER_API_KEY` — `.env`-ში (ჩაწერს მფლობელი; სახელი `.env.example`-შია). `decide.py` მას გარემოდან ან თავად `.env`-იდან კითხულობს და არსად ბეჭდავს; ფორმატის შემოწმება არ უშვებს, რომ დაზიანებული გასაღები შეცდომის ტექსტში მოხვდეს. აგენტი `.env`-ს არ კითხულობს.
9. **გამორთულია.** `[decision] enabled = false`. სანამ ასეა, `decide.py` მხოლოდ `status`-სა და `--dry-run`-ს ასრულებს, ნამდვილ `route`-ზე → exit 3. ჩართვა მფლობელის გადაწყვეტილებაა (P-004), დაცული ფაილის ცვლილებით და ორი წინაპირობით: გასაღები `.env`-შია და კალიბრაცია ჩატარდა — ~30 ნიმუში დავალება, Jev-ის ზოლი ეტალონთან შედარებით, ზღვრის არჩევა, ფასი და სიჩქარე ჟურნალიდან.

## განხილული ალტერნატივები

- **დეტერმინისტული წესები (საკვანძო სიტყვები, ფაილების რაოდენობა):** უფასოა, ზუსტად პროგნოზირებადი და ტესტირებადი, მაგრამ თავისუფალ ტექსტზე — მით უმეტეს ქართულზე — მყიფეა. ძირითად მექანიზმად უარყოფილია; მისი უმარტივესი ფორმა — „ეჭვისას Sonnet" — იატაკად რჩება.
- **Haiku 5.5 დისპეჩერად (`claude -p`):** ერთი ოჯახი და ერთი გამოწერა, მონაცემები ახალ სერვისზე არ გადის; მაგრამ კალიბრირებულ ალბათობას არ აბრუნებს, ჩადგმული გამოძახება უფრო ნელია, Haiku 5.5-ის ქართული კი გაზომილი არ არის. რჩება მეორე პროვაიდერის კანდიდატად, თუ კალიბრაციაში Jev ვერ გამოდგება.
- **დისპეჩერის გარეშე (მოდელს ხელით ირჩევს სესია ან მფლობელი, `/model`):** ხარჯი და რისკი ნულია, მაგრამ ავტორს decision model ძრავში უნდოდა, ხელით არჩევანი კი არათანმიმდევრულია. უარყოფილია ავტორის მოთხოვნით — თუმცა გამორთულ მდგომარეობაში სწორედ ასე მუშაობს.
- **Jev პირდაპირ TypeSafe-ის API-თ:** მოსაწვევი სჭირდება, OpenRouter კი იმავე მოდელს მის გარეშე იძლევა. ახლა უარყოფილია.

## შედეგები

- \+ მექანიკურ დავალებას ყველაზე იაფი მოდელი იღებს, ისე რომ აგენტს გამოცნობა არ უწევს; ერთი გადაწყვეტილება ავტორის გაზომვით ~$0.00004 ჯდება.
- \+ ყოველი გადაწყვეტილება ჟურნალშია — ჩანს, მოწმდება, იზომება.
- \+ ფენა პროვაიდერზე არ არის მიბმული, ნაგულისხმევად გამორთულია, მარცხი კი Sonnet-ზე გადასვლაა და არა გაჩერება.
- − ახალი გარე სერვისი: დავალების აღწერა მანქანიდან გადის (OpenRouter-სა და TypeSafe-ზე). რისკს საზღვარი და შემოწმება ამცირებს, მაგრამ აღწერაში შეიძლება მოხვდეს მგრძნობიარე ფაქტი, რომელსაც შაბლონი ვერ დაიჭერს.
- − API „alpha"-ა: შეიძლება შეიცვალოს ან გაქრეს; პროვაიდერის ფენა და ჟურნალი ჩანაცვლებას იაფს ხდის.
- − ერთი გასაღები და ერთი ბალანსი მეტი (OpenRouter წინასწარ გადახდილია; HTTP 402 → ნაგულისხმევი ზოლი).
- − Jev-ის სიზუსტე ქართულ აღწერებზე უცნობია (ავტორის გაზომვაში დარწმუნებულობა დაბალი იყო) — კალიბრაცია ჩართვამდე სავალდებულოა.
- − დისპეჩერი მხოლოდ „რომელ მოდელს" პასუხობს; რამდენი პროცესი სჭირდება დავალებას (spec, გეგმა, review), ცალკე საკითხია.

## დადასტურება

დრილის ახალი ჯგუფი `decision` (კოდთან ერთად): გამორთული → exit 3 საკუთარი მარკერით; `--dry-run` არაფერს იძახებს და არაფერს წერს (საკონტროლო); ელფოსტის, ტელეფონის ან 11-ნიშნა ნომრის შემცველი აღწერა → exit 5 ქსელურ გამოძახებამდე; ამოწურული ბიუჯეტი (ჟურნალი წინასწარ შევსებული) → exit 4 და ზოლი `code`; ზღვარს ქვემოთ გაყალბებული პასუხი (`routine`, 0.6) → `code`; ზღვარს ზემოთ → შეთავაზებული ზოლი (საკონტროლო); გასაღების გარეშე → exit 1, შეტყობინებაში გასაღების კვალი არ არის; გაყალბებული HTTP 402 → ზოლი `code`. ჩართვისას — ერთი ცოცხალი `route` გამოძახება (L-009), დრო და ფასი ჟურნალიდან.
