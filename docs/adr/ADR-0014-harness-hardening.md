# ADR-0014: Harness-ის გამკვრივება

## კონტექსტი

2026-10-31-ის აუდიტმა და მისმა გადამოწმებამ Fable 5.1-ით (ძრავის სახელოსნოს კვლევის საქაღალდე — ნაკრებში არ შედის) harness-ში (ნებართვების, hook-ებისა და guard-ის ფენა — [[ADR-0004-harness-permissions-hooks-guard]]) სამი ადგილი აჩვენა, სადაც დაცვა სიტყვაა და არა მანქანური შემოწმება:

1. **კარიბჭის ფაილები ნებართვის გარეშე.** `tools/gates/README.md` წერდა, რომ `gates.toml` და `drill.py` „დაცული ფაილებია — ცვლილებას მფლობელი ადასტურებს", მაგრამ ნებართვების სიაში (`.claude/settings.json`: deny 67 / ask 70 / allow 42 სახელოსნოში, 67 / 76 / 38 ნაკრებში) `tools/gates/`-ზე არცერთი წესი არ დგას; AGENTS.md-ის „მფლობელის კი-ს გარეშე არ იცვლება" მხოლოდ პროზაა. commit-ზე დრილი გამორთულ ან დასუსტებულ კარიბჭეს იჭერს (2026-10-31-ის მუტაციის ცდა: `secrets` კარიბჭე გამორთული → 21 DEAD; გაყალბებული PASS → 18 DEAD), მაგრამ თავად `drill.py`-ს ვერ იცავს — ვინც დრილს ასუსტებს, დრილითვე ვერ დაიჭირება.
2. **ჩავარდნილი guard ჩუმად უშვებს.** `.claude/hooks/guard.py`-ის `main()` გაურკვეველ შეტანაზე 0-ით გადის („UNPARSEABLE payload let through"), ავარიაზე — 1-ით, რაც Claude Code-ისთვის არადამბლოკავი შეცდომაა; hook-ის ჩანაწერს `onFailure` არ აქვს, ნაგულისხმევი კი `continue`-ა (Claude Code 2.1.295-დან არსებობს `"onFailure": "block"`; აქ დაყენებულია 2.1.316). L-020 სწორედ ეს იყო: PATH-ზე Python-ის გარეშე ყოველი hook 1-ით ჩავარდა — guard-ი და sentinel-ი გამორთული, brief-ი არ მოსულა, აგენტმა არაფერი იცოდა.
3. **sandbox არ არის და არც ჩანს.** Claude Code-ის sandbox-ი (ბრძანებების იზოლირებული გაშვება — ფაილური სისტემა და ქსელი შეზღუდული) macOS-ზე, Linux-სა და WSL2-ზე მუშაობს და ნაგულისხმევად გამორთულია; ბუნებრივ Windows-ზე არ არსებობს („runs commands unsandboxed"). ნაკრების settings-ში `sandbox` ბლოკი არ არის, README-ში sandbox/WSL2 არ იხსენიება, status line-ი მდგომარეობას არ აჩვენებს. Anthropic-ის დოკუმენტაცია პირდაპირ ამბობს, რომ Bash-ის deny/ask წესი „არ არის უსაფრთხოების საზღვარი პროგრამის გარშემო", Read-წესები კი „best-effort"-ია — ნამდვილი საზღვარი sandbox-ია.

ამას ემატება auto-რეჟიმის ციფრები (Anthropic, 2026-03-25): ნებართვის ფანჯრების 93%-ს ადამიანი ისედაც „კი"-ს ეუბნება, კლასიფიკატორის false-negative (საშიში მოქმედება, რომელიც უსაფრთხოდ ჩაითვალა) 17%-ია — ამიტომ ნამდვილი საზღვარი deny/ask სიებია, რომლებიც auto-რეჟიმშიც მოქმედებს („If an explicit ask rule matches, Claude Code asks you instead, even in auto mode").

## გადაწყვეტილება

1. **ask-წესი კარიბჭის ფაილებზე.** `.claude/settings.json`-ის `ask` სიას ემატება `Edit(/tools/gates/**)` და `Write(/tools/gates/**)` (წამყვანი `/` — პროექტის ფესვიდან, როგორც არსებული `Read(/secrets/**)`): კარიბჭის, მისი კონფიგურაციისა და დრილის ყოველი ცვლილება მფლობელის ფანჯარაა, არა აგენტის გადაწყვეტილება. `deny` არა — სახელოსნო თავად ცვლის ამ ფაილებს (ADR-0013-ის აშენებამ დრილს ახალი შემთხვევები დაამატა), და ასლებშიც მფლობელის „კი"-თ უნდა იცვლებოდეს. `tools/gates/README.md`-ის ფორმულირება მერე ისევ „დაცული ფაილებია" გახდება — უკვე მანქანური წესით.
2. **ჩავარდნილი guard ბლოკავს.** PreToolUse-ის guard-ჩანაწერს ემატება `"onFailure": "block"`: თუ hook-ი ვერ გაეშვა (Python არ არის, `py.sh` ჩავარდა, დრო ამოიწურა), ხელსაწყოს გამოძახება ჩერდება და ადამიანი ხედავს მიზეზს — ჩუმი „guard-ი გამორთულია" აღარ ხდება. guard-ის საკუთარი ორი გზაც იკვრება: გაურკვეველი შეტანა და ავარია 2-ით გადის (დამბლოკავი შეცდომა) ერთხაზიანი ქართული ახსნით, რა გატყდა და რა გააკეთოს ადამიანმა (ტერმინალის ხელახლა გახსნა, L-020). sentinel-ი (PostToolUse) იგივეს არ იღებს — ის გამოტანას ასუფთავებს და მისი ჩავარდნა უკვე R2-ით არის მონიშნული ([[ADR-0007-ai-security-and-observability]]).
3. **sandbox-ი ჩართული, სადაც არსებობს, და მდგომარეობა ყველგან ხილული.** ნაკრების settings-ში `sandbox.enabled: true` (ზუსტი გასაღებები აშენებისას დოკუმენტაციიდან მოწმდება, არა მეხსიერებიდან), ქსელი — allowlist-ით (git-ის remote, API-ის ჰოსტი; დანარჩენი — ფანჯარა); Windows-ზე, სადაც sandbox-ი არ არის, არაფერი ტყდება — `firstrun.py` ერთხელ ამბობს, რომ sandbox-ი არ არის და რას იძლევა WSL2, README-ს ემატება WSL2-ის აბზაცი, status line-ი კი მდგომარეობას აჩვენებს (`🛡 sandbox` / `🛡 sandbox არ არის — Windows`). ნაგულისხმევი ჩართვა მხოლოდ ცოცხალი ცდის შემდეგ macOS-ზე ან Linux-ზე (კარიბჭეები, commit, ნაკრების CI სამივე სისტემაზე) — proxy-ს გავლით ქსელმა შეიძლება რამე დაბლოკოს, და ეს ჯერ უნდა გაიზომოს.
4. **auto-რეჟიმი რჩება; საზღვარი — სიებია.** `disableAutoMode` ნაკრებში ნაგულისხმევად არ იდება: ask/deny სიები auto-რეჟიმშიც მოქმედებს, ჩართვა კი თითო პროექტის მფლობელის არჩევანია (ერთი ხაზი settings-ში). ამის სანაცვლოდ 1–3 პუნქტები სიებს აძლიერებს — სწორედ იქ, სადაც კლასიფიკატორი 17%-ში ცდება.
5. **მთლიანობის მანიფესტი — მოგვიანებით, ცალკე.** ძრავის ფაილების (hook-ები, კარიბჭეები, დამტკიცების სკრიპტი, `.githooks`) ჰეშების სია, რომელსაც SessionStart და pre-commit ადარებს, აქ არ წყდება — ის ცალკე წინადადებაა, რადგან სახელოსნოში ძრავის ყოველი ცვლილება მანიფესტსაც ცვლის და ჯერ გასარკვევია, ვინ და როგორ ახლებს მას ასლებში.

## განხილული ალტერნატივები

- **ყველაფერი ისე დარჩეს, როგორც არის** — პროზა + დრილი commit-ზე. უარყოფილია: დრილი თავის თავს ვერ იცავს, ჩუმად გამორთული guard-ი კი L-020-ში უკვე მოხდა.
- **`deny` კარიბჭის ფაილებზე ask-ის ნაცვლად.** უარყოფილია: სახელოსნოში ძრავა სწორედ ამ ფაილებით ვითარდება, ასლებში კი ახალი კარიბჭე (მაგ. სტეკის `lint`/`unit` ბრძანება ADR-იდან) მფლობელის „კი"-თ ემატება — `deny` ამას ფანჯრის ნაცვლად შეუძლებელს გახდიდა.
- **fail-open guard-ის დატოვება** („ხელმისაწვდომობა უსაფრთხოებაზე წინ"). უარყოფილია: დაბლოკილი გამოძახება ხმამაღალია და ერთი ტერმინალის გახსნით სწორდება; გამორთული guard-ი უხმოა და სესიის ბოლომდე შეუმჩნეველი.
- **sandbox-ი სავალდებულო ყველგან.** შეუძლებელია ბუნებრივ Windows-ზე — ნაკრების აუდიტორიის დიდი ნაწილი სწორედ იქ არის; ამიტომ „ჩართული, სადაც არის, ხილული ყველგან".
- **მანიფესტი ახლავე, ამავე ADR-ში.** უარყოფილია: კიდევ ერთი მოძრავი ნაწილი ნაკრების გამოშვებამდე, განახლების წესის გარეშე — ცალკე წინადადებად.

## შედეგები

**+** harness-ის დაცვის სამივე პრეტენზია მანქანური შემოწმება ხდება, არა წინადადება (rule 23: assurance is not evidence); guard-ის ჩავარდნა ხმამაღალია; Windows-ის მომხმარებელმა იცის, რომ sandbox-ი არ აქვს, და რა შეუძლია ამის ნაცვლად (WSL2).

**−** კარიბჭის ფაილებზე ნებართვის ფანჯრები (იშვიათი და განზრახ); ჩავარდნილი guard-ი ყველა ხელსაწყოს აჩერებს, სანამ Python PATH-ზე არ დაბრუნდება — ტექსტმა ზუსტად უნდა თქვას, რა გააკეთოს ადამიანმა; sandbox-ის proxy-ს შეიძლება allowlist-ში ახალი ჰოსტი დასჭირდეს (ცოცხალი ცდა აჩვენებს); `settings.json`-ის ცვლილება ნაკრებშიც უნდა გადავიდეს (PR, CI სამ სისტემაზე).

## დადასტურება

- დრილი, `wiring` ჯგუფი: `settings.json`-ში ორი ask-წესი და guard-ჩანაწერის `onFailure: block` არსებობს; მუტანტი (წესი ამოღებული / `continue`) → DEAD.
- დრილი, `guard` ჯგუფი: გაუმართავი JSON stdin-ზე → exit 2 და ქართული ერთი ხაზი; ავარიის გზა (განზრახ ჩაგდებული გამონაკლისი) → exit 2; მუტანტი (`return 0`) → DEAD.
- ცოცხალი ნებართვის ზონდი (სუფთა ასლი, `--setting-sources project,local`): `tools/gates/gates.toml`-ის რედაქტირება ფანჯარას ხსნის; წესის გარეშე მუტანტი გადის — ორივე შედეგი ეპიზოდში ჩაიწერება.
- sandbox-ი: macOS-ზე ან Linux-ზე ცოცხალი `claude -p` სესია `sandbox.enabled`-ით კარიბჭეებსა და commit-ს გაივლის; status line-ის დრილი ორივე მდგომარეობას აჩვენებს (ჩართული / Windows).
- ეს ADR მხოლოდ გადაწყვეტილებაა: ცვლილებები `/approve adr 0014`-ის შემდეგ, თითო ცალკე commit-ით, თითო დრილითა და მუტაციით.
